## 2. 卡片如何划分

当前 AEB 示例采用：PRD 概览、功能概述、目标与使用场景、预期功能、后续工作。用户已明确移除“需要进一步确认”模块。

**本轮设计默认：卡片是同一份 PRD 的展示分组，不是新的业务对象。** 五组名称、数量及排序不是固定 PRD 字段，不把自由文本 PRD 改造成必须填写五块的表单。内容有不同章节时，应按实际内容组织；全文仍属于同一 PRD。移除该卡片不表示工程指标已经确认；其他正文中的 TBD 和待确认边界保留。

未添加逐卡片勾选、接受、放弃、单独会话或独立标签。右侧产物卡中的勾选仍选择整份 PRD，与正文的展示分组不是同一种概念。

## 3. 保留的操作逻辑

1. 初次生成成功，原工作标签从默认全宽对话切为正文 + 当前对象 AI，不等待接受。
2. 同一 PRD 重复打开仍激活已有标签；卡片化不新增标签或会话 ID。
3. 顶部编辑入口针对整份 PRD；原型中的“点击功能概述填入示例”仍只是编辑演示，非已实现任意单元格输入。
4. 保存仍为待处理，不自动接受；取消恢复未保存前内容。原文字节点及字符绑定保留，未把正文重新生成成另一份静态副本。
5. 接受 / 放弃仍在右侧产物审阅区，作用于整份 PRD；放弃保留二次确认。没有搬成每张正文卡片的独立按钮。
6. 生成 UC 仍受整份 PRD 接受状态控制；底部下一步入口固定，未接受时不可用。
7. 卡片纵向独立滚动；标签栏、对象工具栏、下一步入口不随正文滚走；AI 消息区独立滚动，输入区保持可用。
8. AI 显示当前对象 PRD · AEB 和独立会话。输入草稿、附件及消息跟随对象；PRD 专属自动扩写仍为回填，不自动发送。
9. LKA 新建工作仍使用无产物默认工作区，没有为截图伪造 LKA 输出。将来任意 PRD 输出可复用该组件结构，但须传入自己的内容和对象身份。
