# 前端页面交互规则

> 版本：V1.0（UC 全景 / FR 分配全景前端接入）  
> 定位：本项目所有前端组件交互的统一维护入口。新增、调整或移除交互时，必须同步更新本文件和对应测试，不只把结论留在聊天记录。  
> 来源优先级：用户最新明确要求 > 本文件已确认规则 >《标签页与左侧导航交互规范》细则 > 设计默认 > 历史设计图。  
> 状态约定：**已确认**为用户明确要求；**实现默认**为本轮实现采用的可调整规则；**待确认**不得自行补成业务能力。  
> 当前能力：前端本地交互演示 + 既有认证；生成、AI 和业务保存不是生产后端能力。刷新 / 退出会清空本页模拟数据。

## 1. 维护约束

1. 每个新增组件 / 状态必须明确：触发入口、作用对象、状态变化、可修改范围、成功 / 失败 / 空状态、关闭与键盘行为、持久化边界。
2. 修改已有规则时原位更新主规则，同时在第 12 节写变更说明；不能只在末尾追加相互矛盾的要求。
3. 未说明的业务规则记入第 11 节。不能因为 Figma 存在按钮或可编辑图层就推导出后端能力。
4. 局部实现只参考用户指定区域。本轮仅参考 UC / FR 分配全景正文，不覆盖 Figma 图中其余壳层；保持现有顶栏、侧栏外观、PRD / UC / FR 详情布局。
5. Figma Page 仅组织设计，不是路由或业务对象。汇总视图不构成新增的第五类对象。
6. 组件代码变更后运行 lint、typecheck、单元测试、build，并回归相关浏览器交互；检查结果记录到实施计划。
7. 详细生命周期与场景沿用 [标签页与左侧导航交互规范](E:/Git%20projects/TS-frontend/docs/标签页与左侧导航交互规范.md)。如果细则与本文件新增确认冲突，以本文件为准，并同步修订细则。

### 2.1 身份与去重

- 普通对象：项目 + 对象类型 + 稳定对象 ID。名字、编号展示文本和标签序号不能充当跨业务功能主键。
- 全景：项目 + 业务功能 ID + 全景类型。UC、FR、FR 分配是三个不同视图；同一类型跨业务功能也独立。
- 本地存储按项目分区；FR 实例 ID 包含业务功能身份，防止两个业务功能的相同展示编号覆盖彼此。
- 新标签插入当前业务标签旁；重复打开只激活，不能重建正文、清空会话或丢弃输入。
- 第一次 PRD 成功会激活原标签，覆盖历史“所有异步结果一律不抢焦点”的泛化规则。后续修改结果不强制切换；任务仍归原项目。**不会为了激活 PRD 自动切换用户当前项目**。
- 批量生成 UC 不自动打开每条 UC；生成后源对象出现，UC 全景数据自动刷新，不强行新开或激活全景标签。

## 5. PRD 默认区、扩写与结果

- PRD-01：无 PRD 正文的新建工作使用既有全宽默认 AI 工作区，显示当前业务功能 / PRD 生成身份；有正文后展示正文 + 右侧同一会话。
- PRD-02：自动扩写作用于已输入的提示词；空输入不可触发；等待显示加载状态。成功只回填，不发送、不生成 PRD、不自动截断原输入。
- PRD-03：发送执行当前 PRD 生成 / 修改流程；运行中不得重复提交；Ctrl / Cmd + Enter 发送，普通 Enter 换行，输入法组合态不发送。
- PRD-04：首次成功遵循 TAB-02；生成期间另输入的草稿继续保留，不能被请求完成清空。
- PRD-05：结果卡片是同一份 PRD 的分段，不新增逐卡对象 / 审批；不恢复“需要进一步确认”卡片。
- PRD-06：编辑 / 取消 / 保存 / 接受 / 放弃沿用既有逻辑。保存只是草稿；放弃产物和关闭标签是两种动作；不能跳过所需确认。
- PRD-07：生成 UC 要求 PRD 已接受。失败 / 停止不损坏上游 PRD；成功批量创建 UC 而不自动弹出所有 UC 标签。
- PRD-08：新建业务功能采用既有去重和名称校验；同名打开已有工作，不悄悄创建第二份 PRD。

## 8. FR 全景及 FR 详情（保留并接线）

- FR-01：FR 全景仍是需求编号 / 需求来源 / 需求描述三列；只参考既有前端数据，不替换为 Figma 示例内容。
- FR-02：FR 文件夹名称打开 / 去重全景，drop 只展开；编号和左侧实例可打开对应 FR 详情。
- FR-03：同业务功能详情保存后，FR 全景与分配全景都读取当前 committed 文档；不读取过期副本或未保存草稿。
- FR-04：详情继续现有编辑 / 校验 / 保存 / 取消 / 接受流程，不把分配页只读规则误套到详情页。
- FR-05：表格与 FR 正文使用中性样式，不重新迁回黄色高亮、红色字体或彩色编号。业务状态、导航激活、焦点不属于被禁的表格来源样式。

## 9. FR 分配全景（本轮新增）

| 列 | 权限 | 行为 |
|---|---|---|
| 需求编号 | 只读 | 显示原 FR 内容；本页编号不提供编辑 / 跳转按钮 |
| 需求来源 | 只读 | 保留原文，长文换行 |
| 需求描述 | 只读 | 保留原文和法规来源，长文撑高本行 |
| 子系统名称 | 唯一可修改 | 每行一个可搜索多选下拉框 |

- ALLOC-01：页面没有“编辑 / 进入编辑 / 保存整表 / 取消编辑”按钮，不存在先进入编辑模式的步骤。
- ALLOC-02：沿用已确认的一个 FR 可分配多个预置子系统，因此下拉支持多选。
- ALLOC-03：候选来自独立预置目录；当前使用演示目录，不能把它当作正式架构。用户不能在这里创建、重命名或停用子系统。
- ALLOC-04：每行选择只影响该行分配关系；不同 FR、业务功能、项目隔离；FR 原文保持不变。
- ALLOC-05（实现默认）：勾选即时更新本页状态；“完成”只收起浮层，不是后台保存。允许取消最后一项恢复未分配。
- ALLOC-06：搜索实际按输入匹配名称，支持任意关键词，不再是 Figma 的预设关键词跳转。搜索不改变表格行，也不清除不在当前结果中的已选项。
- ALLOC-07：无结果提示换词 / 清空，不提供新增入口；清空恢复全部候选。
- ALLOC-08：展开显示当前 FR 编号和选中数量；折叠显示首个名称及多选数量，完整名称可在展开 / 悬停时查看。
- ALLOC-09：点击外部、关闭、完成或 Escape 收起；完成 / Escape 将焦点还给原触发框。切换标签 / 项目时浮层关闭，不在另一个工作页悬浮。
- ALLOC-10：打开后焦点进入搜索；方向键定位候选、空格切换原生复选框；Tab 在浮层内移动，完成 / Escape 可退出。
- ALLOC-11：浮层通过 Portal 避免被表格裁切，依据可用空间向上 / 向下定位，滚动和窗口尺寸变化同步定位；原行离开视口时关闭。
- ALLOC-12：表头固定，四列随同一表格滚动，行高由长文决定；不重复渲染一套有偏差的表头。
- ALLOC-13：初始未分配；不根据描述里的“xxx”猜测归属。选择保留在本页内，关闭重开可恢复；刷新 / 退出 / 跨设备持久化尚未实现。
- ALLOC-14：真实保存 API、失败回退、审阅与冲突策略未接入；不得用成功提示冒充已保存到服务端。

## 10. AI、通用弹窗与反馈

- AI-01：正文、会话、输入草稿、附件必须绑定当前工作身份；项目和业务功能不能混用同一全局会话。
- AI-02：添加 / 删除附件不自动发送；正在执行的请求使用开始时的引用快照，后续候选变化不修改已发请求。
- AI-03：PRD / UC / FR 既有模拟流程保留；本轮新增全景对话仅记录提问并明确提示未调用真实 AI，不修改只读源数据或代替下拉分配。
- AI-04：失败、重试、取消和关闭均保留明确状态；取消后的迟到回调不能写入新对象。
- UI-01：对话框关闭不能隐式确认危险操作；已有保存 / 放弃 / 停止确认继续生效。
- UI-02：提示可关闭但不代表业务状态被撤销；无数据、搜索无结果、不可用入口都给出可理解说明。
- UI-03：所有按钮、搜索框、复选框都有可访问名称；可操作控件显示焦点；图中只读节点不伪装成按钮。
- UI-04：本轮未重新设计的账户、主题、PRD / UC / FR 详情组件继续按现有功能工作，不因参照新 Figma 画面而覆盖。
