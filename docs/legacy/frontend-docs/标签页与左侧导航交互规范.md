## 2. 术语与职责

| 概念 | 示例 | 职责 |
|---|---|---|
| 项目 | 项目 A | 对象、标签集合、会话与任务的隔离边界 |
| 一级模块 | 产品工程、需求工程 | 组织平台功能入口 |
| 平台功能 / 工作阶段 | PRD生成、场景分析、功能设计、功能分配 | 决定操作能力、Agent 工作身份和上游约束 |
| 业务功能 | AEB、LKA、儿童锁 | 同一项目中的独立研发主题 / 功能根 |
| 业务对象 | 某份 PRD、某条 UC、某条 FR | 持久业务内容；独立身份，不以名字作为主键 |
| 对象标签 | UC-XXX-01-17 · HMI 软开关控制儿童锁 | 打开对象的视图，关闭标签不删除对象 |
| 新建工作标签 | 新建 PRD · 新功能 | 尚无产物时的临时工作入口，持有临时 ID 和独立会话 |
| 会话 | 当前 UC 的讨论、修改记录 | 跟随当前对象 / 临时工作标签，不是全局共享聊天 |
| 浏览位置 | 左侧正在浏览的模块 / 目录 | 可以暂时不同于当前标签的对象归属 |

总原则：**左侧寻找和打开工作；顶部保留和切换已打开对象；正文显示当前对象；AI 对话服务当前对象。**

## 3. 整体布局

- 保留全局顶部：项目切换、当前工作路径、账户、主题等。
- 保留单侧栏：全部功能 / 当前模块功能 / 当前模块工作空间互斥显示，不额外堆叠常驻导航列。
- 左侧以外的完整区域属于标签容器：标签栏在上，中央正文与右侧 AI 位于其下。
- 标签切换时正文和 AI 同步切换，不能出现“正文是 AEB、聊天却仍在修改 LKA”。
- UC 长表在中央正文区域独立纵向滚动；标签栏、对象工具栏和侧栏不跟随表格滚走；AI 消息区单独滚动，输入区保持可用。
- 桌面主稿目标为 **1440 × 900**；完整表格长稿用于交接结构，不代表实际应用必须拉长窗口。
- 明亮 / 深色使用同一语义变量和组件；深色不是简单反色。
- 第一版多标签是“多个页面保持打开、切换显示”，不自动包含并排分屏或独立浏览器窗口。

## 4. 标签身份、命名与打开规则

### 4.1 唯一身份（设计默认）

- 普通对象标签的去重键为 `projectId + objectType + objectId`。
- 对象身份不使用名称、列表序号、所在导航位置作为唯一标识；对象重命名不新建标签。
- 新建工作先使用 `projectId + creationSessionId`；生成首个目标对象后，将当前标签绑定到正式对象身份，保留会话与输入。
- 同一对象从导航、目录、AI 产物卡、搜索结果或引用链接打开，默认定位到已有标签。
- 第一版不允许同一个对象出现两个互不一致的可编辑副本。版本比较、同对象双视图属于后续能力。

### 4.2 显示名称（设计默认）

- PRD：`PRD · 儿童锁` / `PRD · AEB`。
- UC：优先显示 `UC-XXX-01-17 · HMI 软开关控制儿童锁`；窄标签截断名称，完整名称由悬停提示与正文标题提供。
- FR / FR分配：对象类型 + 稳定编号 + 可读名称。
- 同名跨业务功能时补充所属业务功能，不只展示“未命名对象”。
- 尚未产生对象：`新建 PRD · 新功能`；用户命名后及时更新，不丢失临时会话。

### 4.3 打开与创建（设计默认）

1. 点击对象：存在标签则激活；不存在则在当前标签右侧打开并激活。
2. 单击对象名称即正式打开，不引入“单击临时预览、双击固定”的第二套隐式规则。
3. 点击二级功能是进入能力入口，**不是无条件创建新对象**。
4. 有当前业务功能上下文时，二级入口优先返回该上下文最近使用的相关对象 / 新建工作；有歧义时显示业务功能选择器。
5. 无可恢复工作时，进入明确的新建 / 选择对象入口，不能擅自修改旧对象或自动复制数据。
6. 多产物生成后，产物先进入工作空间与会话产物列表；点击单项打开其对象标签。提供“打开选中项”可作为后续批量入口；不默认强制打开全部结果。
7. PRD 首次生成后，原新建标签绑定 PRD 并显示正文，不同时遗留“新建 PRD”和“同一 PRD”两张重复工作页。

## 5. 标签页与左侧导航如何同步

### 5.1 状态必须分开

至少区分：
- `activeTabId`：当前正在工作的对象标签；
- `sidebarView`：全部导航 / 模块功能 / 工作空间；
- `sidebarBrowseContext`：侧栏正在浏览的模块、业务功能、目录；
- `sidebarSelectedObjectId`：当前定位的对象，不等于勾选附件；
- `checkedObjectIds`：勾选候选对象，和打开行为分离。

**当前标签决定工作上下文；左侧允许浏览其他位置。** 不要使用一个 `selectedModule` 同时驱动侧栏浏览与正文对象。

### 5.2 操作矩阵

| 操作 | 左侧行为 | 标签 / 正文 / AI 行为 | 状态 |
|---|---|---|---|
| 点击一级模块箭头 | 展开或收起二级功能 | 不切换、不关闭当前标签 | 设计默认 |
| 点击一级模块名称 | 进入该模块的侧栏内容 | 当前工作保持不变 | 设计默认 |
| 点击二级功能 | 定位相应能力入口 | 恢复对应上下文工作；无工作则进入选择 / 新建入口 | 设计默认 |
| 返回全部功能 | 回到全部功能导航 | 不重置当前标签 | 设计默认 |
| 切换“功能 / 工作空间” | 仅切换侧栏视图 | 不改变当前正文、草稿、会话 | 设计默认 |
| 点击文件夹 drop | 仅展开 / 收起子项 | 不打开标签 | 已确认 |
| 点击 UC / FR / FR分配文件夹名称 | 打开对应全景 | 已打开则激活，不重复创建 | 已确认 |
| 点击对象名称 | 定位该对象 | 打开 / 激活其独立标签，同步正文与该对象 AI | 已确认 |
| 勾选对象 | 更新候选附件选择 | 不打开、不切换、不自动引用 | 既有规则延续 |
| 点击顶部标签 | 当前工作标记跟随，工作空间模式定位对象 | 正文、对象工具栏、会话、草稿、附件一起恢复 | 已确认 + 设计默认 |
| 在另一模块中浏览目录 | 允许暂时浏览其他位置 | 不改变当前 AI 的任务身份 | 设计默认 |
| 点击“定位当前对象” | 展开祖先并滚动定位当前对象 | 不创建新标签 | 设计默认 |

### 5.3 同步细节

- 切标签时尽量保留侧栏视图类型，不强迫每次跳到工作空间。
- 当前对象所在模块显示工作状态标记；侧栏正浏览的模块用独立标题表示，不能让两者视觉混淆。
- 若搜索过滤隐藏了当前对象，提示“当前对象被筛选隐藏 / 定位当前对象”；不要静默清空搜索。
- 侧栏查询、目录展开状态可按项目 / 模块保存；切换项目不能沿用错误目录选中。
- 顶部面包屑反映当前标签的真实上下文，不能被临时浏览其他模块覆盖。

### 5.4 添加到 AI 的明确目标

- “打开对象”“勾选对象”“加入当前对话”是三个动作。
- 按钮应显示目标，例如 `添加到当前对话：UC-XXX-01-17`，而不是无法识别目标的全局添加。
- 用户可保持目标 UC 标签激活，在侧栏浏览其他 PRD / UC，勾选后加入目标会话。
- 如果当前无可接收附件的标签，按钮禁用并说明，或明确选择目标工作；不能使用隐藏的上一次标签。
- 切标签后目标文案即时更新；执行时校验目标与用户看到的一致，不能把附件加到迟到 / 隐藏会话。
- 重复引用去重，移除引用不删除源对象；查看对象不等于自动引用。

## 6. AI 与对象标签的绑定（已确认）

1. 每个对象标签恢复自己的会话、输入草稿、附件与任务状态。
2. `UC-XXX-01-17` 的讨论不能混入 `UC-XXX-01-13`，即使属于同一业务功能 / 同一阶段。
3. 输入框上方显示当前作用对象：类型、编号 / 名称；避免仅写“场景分析”而看不出正在修改谁。
4. 切标签不清空输入、不自动发送、不自动接受产物、不自动停止任务。
5. 跨对象引用需要明确的引用关系；所有打开标签的内容不能自动作为全局 AI 上下文。
6. 新对象的初始会话可以记录“来源于哪次生成、上游对象是谁”，但不默认复制整段上游私有对话。
7. 多对象批量生成任务在新建工作会话中进行；每个结果对象打开后有自己的对象会话，保留来源任务链接。结果会话的初始化文案属于设计默认，实际消息复制范围待确认。
8. 同一个对象跨入口重新打开，恢复同一对象会话，不因标签关闭再开就永久生成新会话。
9. 任务结果按 `projectId + businessFeatureId + objectId/creationSessionId + taskId` 回写；不能按“响应回来时的当前标签”写入。

## 7. 同项目多业务功能与新建入口（已确认方向）

### 7.1 建议入口

- 产品工程 → PRD生成：进入该项目 PRD 工作入口，展示已有业务功能，并提供 `新建 PRD`。
- 标签栏 `＋`：打开轻量创建 / 打开菜单，不立刻产生一个意义不明的空白标签。
- 菜单至少区分 `打开已有对象` 与 `新建 PRD 工作`；UC/FR 等阶段入口带有上游条件说明。

### 7.2 新建 PRD 的设计默认流程

1. 选择“新建业务功能”或“已有业务功能”。
2. 新建时填写业务功能名称（例如 LKA），避免只输入“新建 PRD”而无所属主题。
3. 已有功能若已有 PRD，优先提供“打开已有 PRD”；不自动生成第二份冲突 PRD。多 PRD / 版本策略待确认。
4. 确认后打开独立临时工作标签，显示 PRD 默认工作区与独立 AI 输入。
5. 已有 AEB 标签保持打开；LKA 与 AEB 的数据、会话、草稿与附件隔离。
6. 首次生成成功，当前临时标签绑定正式 PRD 对象，原地切换正文 + 右侧同一对话。
7. 取消创建不创建业务对象；关闭未提交的空白新建标签不影响已有功能。

### 7.3 下游工作

- 从已接受 PRD 进入场景分析，显式携带上游对象身份 / 版本，原 PRD 标签保留。
- 从 UC 到 FR、从 FR 到分配，沿用相同原则；实际解锁条件以相应业务需求为准。
- 从现有对象发起下游操作，不应静默切换到另一个业务功能的最近任务。
- AEB 与 LKA 同时打开是目标能力；不能通过让两个标签引用当前每项目唯一 PRD 状态来“伪实现”。

## 8. 切换、关闭、保存与任务

| 情况 | 设计默认行为 |
|---|---|
| 切换标签 | 保留阅读位置、编辑位置、未保存正文、提示词、附件、产物选择与任务状态 |
| 关闭普通已保存标签 | 直接关闭视图，回到最近使用的仍打开标签 |
| 关闭待接受但已保存对象 | 不执行“放弃”，工作空间仍保留待处理对象 |
| 正文有未保存修改 | 弹窗：保存并关闭 / 不保存并关闭 / 取消；保存失败保持标签打开 |
| 有未发送输入 | 按对象保存草稿；若尚无恢复能力，关闭前提示，不能静默丢失 |
| 关闭最后一个业务标签 | 回到工作台，不显示无法操作的空壳 |
| 切换到其他标签时任务仍在运行 | 任务归属不变；首次 PRD 成功按最新要求激活原标签，其他结果不抢焦点，不自动切换项目 |
| 没有后台任务中心时关闭运行中标签 | 明确提示“停止并关闭 / 继续留在此页”；不伪装已移交后台 |
| 有后台任务中心后关闭运行中标签 | 可选择后台继续，提供可重新打开的任务入口 |
| 删除源对象 | 与关闭区分，确认删除后打开标签展示对象已删除 / 关闭提示；不得仍允许提交修改 |
| 会话过期 | 保护可恢复草稿并要求重新认证，不绕过鉴权 |

**关闭标签 ≠ 删除对象 ≠ 放弃产物 ≠ 停止任务。** 四种动作必须有不同文案和明确结果。

尚无真实后台任务服务时，“切标签继续”只代表当前应用会话仍然运行，不代表关闭浏览器、电脑重启后仍继续。

## 9. 标签数量、排序与状态

设计默认：
- 支持拖动排序、关闭、关闭其他、关闭右侧；批量关闭逐项遵守未保存保护，可聚合确认。
- 工作台永久固定在最左侧，不能移动 / 关闭，已有前端实现；最近关闭列表属于另行确认能力，不能据此混同。
- 标签过多时保持可读最小宽度，横向滚动 + 全部标签列表；不无限压缩成只剩叉号。
- 全部标签列表显示完整名称、所属业务功能和状态，可搜索定位。
- 当前标签必须可见；激活溢出标签后自动滚到可见区域。
- 未保存状态与“待接受”分开表示；任务运行、失败、已完成未读也不共用含糊的小圆点。
- 状态不仅依赖颜色：可读标签 / 图标 / 悬停说明并用。
- 不默认占用浏览器的 Ctrl+W / Ctrl+Tab。站内快捷键需与宿主浏览器冲突检查；基础键盘焦点和标签切换必须可用。
- 标签栏使用明确的 tablist / tab / tabpanel 语义；按钮焦点可见，关闭后焦点落到有效相邻 / 最近标签。

## 10. 项目切换与恢复

- 每项目独立标签集合，不把项目 A 与 B 对象混在同一标签栏中。（设计默认）
- 切项目恢复目标项目最后激活的标签；原项目打开对象与草稿保持隔离。
- 切项目不等于关闭旧项目；任务完成提示带项目和对象名称，不自动抢占当前项目。
- 主题与账户是全局偏好；对象内容、会话和任务是项目 / 对象作用域。
- **切回来恢复、刷新后恢复、退出登录后恢复、跨设备恢复是不同能力。** 持久化范围待确认，不能混称“状态已保存”。
- 身份凭据继续使用 HttpOnly Cookie，不因为标签恢复把认证 Token 写入 localStorage/sessionStorage。
- 文档草稿 / 敏感需求是否可本地持久化，需结合数据安全策略另行确认。

## 11. UC 表 7 的强制结构

UC 标签正文是可编辑对象详情表，而不是把截图铺成背景。字段、内容、网格均应保持可编辑。

### 11.1 顶层字段（固定顺序）

| 顺序 | 字段 | 内容规则 |
|---:|---|---|
| 1 | 用例名称 | 完整用例名称 |
| 2 | 用例描述 | 业务目标与意义 |
| 3 | 用例编号 | 稳定 UC 编号，如 UC-XXX-01-17 |
| 4 | 参与者 | 参与角色 |
| 5 | 前置条件 | 条件组合标记（如 a&b&c&d）+ 逐条条件；不适用为 N/A |
| 6 | 场景 | 见 11.2，多级合并 |
| 7 | 后置条件 | 分正常事件流结束状态、异常事件流结束状态 |
| 8 | 扩展用例 | 关联 UC 编号，或 N/A |
| 9 | HMI 交互逻辑 | 文字或截图；可容纳图片，不适用为 N/A |
| 10 | 法规需求 | {法规编号}_{条款号}_{系统}_Req{序号} + 原文；未经核实保留待确认 |
| 11 | 性能需求 | 性能指标文字；待定值保留 TBD，示例不自动转为已确认指标 |
| 12 | 非功能需求 | 其他非功能要求，或 N/A |

### 11.2 场景嵌套结构

整体为左字段列 / 右内容区。场景的左字段列纵向合并 10 个子行；右侧为：

| 一级子标签 | 二级子标签 | 内容 |
|---|---|---|
| 主事件流（正常流程） | 无；内容跨后两列 | 1.、2.、3. 等步骤；可引用 a1～a4、E1～E4 |
| 分支事件流 1 | 无；内容跨后两列 | a1 或 N/A |
| 分支事件流 2 | 无；内容跨后两列 | a2 或 N/A |
| 分支事件流 3 | 无；内容跨后两列 | a3 或 N/A |
| 分支事件流 4 | 无；内容跨后两列 | a4 或 N/A |
| 异常事件流（非正常流程），此标签纵向合并 5 行 | 车辆状态异常 | E1 + 步骤，或 N/A |
| 同上 | 机械故障 | E2 + 步骤，或 N/A |
| 同上 | 环境突变 | 描述或 N/A，不凭空新增 E5 |
| 同上 | 用户误操作（滥用） | E3 + 步骤，或 N/A |
| 同上 | 供电异常 | E4 + 步骤，或 N/A |

- 4 个分支占位、5 类异常全部保留；没有内容填 N/A，不能删除行后改变模板。
- 普通行的右侧内容跨场景内部细分列，整体仍为字段 / 内容的两列关系。
- 保留全边框、浅底字段列、清晰层级；正文可用衬线字体表现文档，界面导航沿用产品字体。
- 标题保留 L3 功能点 → 单个 UC 的层级关系（例如 5.1 与 5.1.1）；章节序号与对象稳定编号不是同一主键。
- 长内容自动增高，禁止省略号隐藏正文；表格在中央滚动，不能缩小到不可读以硬塞进首屏。
- 不用“全表可滚动长截图”冒充 Figma 内有真实可编辑单元格。
- 预览编辑入口与保存 / 取消保留；实际编辑粒度、插入图片和已接受对象修改规则仍待确认。

## 12. 状态归属建议（供后续实现）

| 作用域 | 应持有的状态 |
|---|---|
| 全局 | 登录用户、主题、全局通知 |
| 项目 | 业务功能集合、对象索引、打开标签顺序、最近激活记录 |
| 对象 | 正文、版本 / 修订、审阅状态、来源关系 |

- 对象数据只有一个真源，不能在目录、正文、产物卡、标签标题中维护四份互不相干的副本。

- 临时新建会话有独立 ID；成功绑定对象时迁移关系，不能因标题改名重建整个状态。
- 异步请求具有目标上下文与取消 / 迟到结果保护；对象 A 的结果不能覆盖对象 B。
- 避免当前演示中“每项目唯一 PRD + 一套全局附件 / 预览状态”的结构直接扩展成多标签。
