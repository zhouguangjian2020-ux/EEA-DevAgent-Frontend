# PRD 与 UC 对象级标签页：前端实施说明

> 版本：V1.0 · 日期：2026-09-15 · 适用工程：`E:\Git projects\TS-frontend`
>
> 本文件是实现参照，不替代产品需求和 `docs\标签页与左侧导航交互规范.md`。它区分“当前前端内存演示”“Figma 设计稿”和“真实后端能力”，避免把预设或 mock 当成已上线能力。

## 1. 本轮实现目标

实现 PRD 与 UC 的**对象级标签**，而不是“每个工作阶段一张标签”：

- 一个对象只有一个可编辑标签；重复从目录、标签溢出列表、PRD 下游结果或引用打开时，激活已有标签。
- 同一项目可同时有 AEB、LKA、ACC 等业务功能；每个对象有独立正文、AI 消息、输入草稿、附件、任务身份和阅读滚动位置。
- 左侧是浏览位置，顶部是打开对象；浏览其他模块不能替换当前正文。
- PRD 由默认全宽 AI 工作区开始；首个生成结果在原标签内切换为卡片正文 + 对象专属 AI。
- UC 以附件表 7 的结构呈现：12 个字段、场景主流程 + 4 个分支、5 个异常事件流合并区。
- Light / Dark 共用语义 token；主题只改变外观，不改变对象状态。

## 2. 进入应用与对象入口

### 2.1 产品工程 → PRD生成

1. 点击“PRD生成”进入能力入口。没有当前对象时显示工作台 / 默认 AI 区，不自动创建一个无业务名称的对象。
2. 点击 `＋` 或“新建 PRD 工作”，输入业务功能名称，例如 `LKA`。
3. 名称在本地使用 1～64 字校验，并做 NFKC、大小写、连续空格归一；同名 PRD 优先重新打开，不创建第二份冲突工作。
4. 新工作只有临时身份和独立会话；输入提示词后自动扩写只回填输入框，不自动发送。
5. 生成成功后临时标签原地绑定 PRD 对象；正文卡片和右侧 AI 同时出现，原输入草稿和该对象附件仍归属于该对象。

### 2.2 需求工程 → 场景分析 / UC

- 工作空间目录只展示已有 UC 对象；点击对象名称直接打开标签，不使用“单击预览、双击固定”。
- 可以从已接受 PRD 的“生成 UC”开始本地模拟生成。生成结果写回源 PRD 对象，先进入目录和 PRD 结果列表，**不自动打开全部 UC 标签**。
- 点击单条 UC 或表格中的已知 UC 编号才打开对应 UC 标签；UC-13 与 UC-17 的会话不共享。
- UC 的对话不显示 PRD 专属“自动扩写”；输入框只修改当前 UC，发送操作生成一个新的待处理修订草稿。

### 2.3 “载入 PRD / UC 示例”

工作台提供显式的本地演示入口，载入 AEB 待处理 PRD、儿童锁已接受 PRD、儿童锁 5 条 UC。它用于验收表格、标签和审阅动作；重复载入不会覆盖同名业务功能、用户编辑或未接受状态。真实业务不应把示例入口当成后端初始化。

## 3. 标签与左侧同步规则

| 操作 | 结果 |
|---|---|
| 点击目录对象 | 打开或激活对应标签；定位到所属模块 / 业务功能 |
| 点击标签 | 正文、AI、输入草稿、附件和任务一起切换 |
| 点击一级模块 / 返回全部功能 | 只改变侧栏浏览，不关闭或替换当前标签 |
| 切换侧栏“功能 / 工作空间” | 只改变浏览位置；当前对象仍可从顶部标签继续操作 |
| 搜索隐藏当前对象 | 当前工作区保持，侧栏显示隐藏提示；点击“定位当前对象”清空筛选并滚动到对象 |
| 勾选目录对象 | 只建立附件候选，不打开对象、不自动加入对话 |
| 添加到 AI 对话 | 必须有明确当前对象；只将勾选对象加入当前对象附件，去重且排除自身 |
| 点击工作台标签 | 取消当前对象焦点，但保留全部对象及其标签 |
| 关闭对象标签 | 只关闭视图；对象、正文、会话和附件仍在本页内，可从目录 / 已有对象重新打开 |

标签右侧有关闭按钮但不删除对象；未保存正文或运行任务关闭时进入确认对话。运行任务没有真实后台中心，因此只提供“停止并关闭”或“继续留在此页”，不声称关闭浏览器后继续执行。

## 4. PRD 输出卡片规则

PRD 仍是自由文本，不强制成固定字段表单。`parseFreeText` 按一级 / 二级标题切成阅读卡片：

- 第一张概览卡显示对象标题和整份 PRD 状态。
- 后续每个一级 / 二级章节形成一张卡片；没有章节标题的内容进入概览卡。
- 卡片只是正文展示分组，不是新的对象、标签、会话或审批单元。
- “需要进一步确认”模块已移除；正文中的 `待确认`、`TBD`、法规 / 性能未核实等工程边界保留原文。
- 编辑入口针对整份 PRD，保存后仍为待处理；接受 / 放弃作用于整份 PRD。只有接受后“生成 UC”按钮可用。

## 5. UC 表 7 结构与编辑规则

表格 DOM 顺序固定为：

1. 用例名称；2. 用例描述；3. 用例编号；4. 参与者；5. 前置条件；
6. 场景（主事件流 1 行 + 分支事件流 4 行）；
7. 异常事件流（车辆状态异常、机械故障、环境突变、用户误操作（滥用）、供电异常 5 行）；
8. 后置条件；9. 扩展用例；10. HMI 交互逻辑；11. 法规需求；12. 性能需求；13. 非功能需求。

表 7 的合并表现为：场景分组字段 `rowSpan=10`；异常事件流分组 `rowSpan=5`；主流程 / 分支行内容跨两列；普通字段内容跨三列。环境突变使用 `N/A`，不虚构 `E5`。工程待确认内容只作为当前模板文字，不是确认结论。

- UC 编号稳定且只读；名称、描述、参与者、条件、流程、HMI、法规和性能等内容进入整表编辑。
- 先点击“编辑”，再在单元格输入；“保存”只保存当前内存草稿，不自动接受。
- 接受 / 放弃仍是整条 UC 的审阅动作；放弃前二次确认，对话记录保留。
- 已接受对象本轮不允许普通覆盖式修改；后续版本策略属于 Q04。

## 6. 状态与任务安全

### 6.1 状态边界

`src/features/workbench/model.ts` 维护按项目的 `ProjectWorks`：对象记录、已打开标签、当前标签、MRU、关闭请求和提示。`useWorkbenchStore` 用 `project/workId` 维护 AbortController：异步完成按原目标回写，不按返回时的当前标签回写。

- 切标签 / 切项目不会停止任务。
- 自动扩写、PRD生成、UC更新和批量 UC 生成是本地模板 + 延时；失败显示重试，取消会阻止迟到结果复活。
- 刷新页面重新初始化内存状态；离开前有未保存 / 本地对象提示，但没有数据库或跨设备恢复。
- 真实登录、退出和认证 cookie 沿用既有 `/api/v1/auth/*` 与 HttpOnly 机制，本轮没有修改后端。

### 6.2 关闭矩阵

| 状态 | 关闭行为 |
|---|---|
| 普通已保存对象 | 直接关闭标签，优先回到最近使用标签 |
| 正文未保存 | 取消 / 不保存并关闭 / 保存并关闭；保存校验失败保持标签打开 |
| 运行中任务 | 继续留在此页 / 停止并关闭；不伪装后台运行 |
| 已接受对象 | 标签关闭不改变接受状态 |
| 放弃产物 | 必须从右侧整份审阅区二次确认；这不是关闭标签 |

## 9. 未决问题（按规范保留）

以下没有被本轮前端本地模拟“静默解决”：

- Q01：刷新、重新登录、跨设备恢复范围。
- Q02：同业务功能多份 PRD / 版本创建策略。
- Q03：批量生成结果会话需要继承多少来源摘要或对话。
- Q04：已接受对象如何修改并形成新版本，以及如何影响下游。
- Q05：UC 最终采用整表编辑还是单元格细粒度交互，是否支持 HMI 图片；当前仅采用可交付的单元格文本编辑默认。
- Q06：是否建设后台任务中心；当前不伪装为后台运行。
- Q07：是否需要同对象多版本对照或并排分屏。
- Q08：业务功能正式命名、唯一性、提交与服务端规则；本地去重不等于服务端契约。
