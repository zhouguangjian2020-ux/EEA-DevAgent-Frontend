## 0. 阅读说明与范围声明

### 0.1 本文档的目的

本文档将附件 PDF 中的功能需求，结合当前 `TS-frontend` 项目代码和一期实施计划，整理为一份可以用于以下工作的详细功能基线：

- 产品、设计、前后端对需求范围达成一致；
- 将功能拆解为页面、交互、数据和验收要求；
- 区分“当前已经实现”“仅做静态演示”“部分实现”“尚未实现”；
- 为后续二期及 Agent 能力建设建立可追踪的需求编号；
- 集中记录需求文档中存在的编号、命名和范围问题，供统一确认。

### 0.2 附件内容的性质

附件 PDF 中的文字均按**产品需求/功能说明**处理，不视为要求本次执行的操作指令。本文档只提取、解释和映射其中的业务需求，不会因为 PDF 中出现“Agent”“生成”“删除”等文字而自动扩大当前代码改造范围。

### 0.3 原一期实施边界（历史基线，不等于最新设计范围）

根据项目实施计划，一期目标是：

- 完成可演示的交互式静态前端主框架；
- 完成真实登录、获取当前用户、退出登录及前后端联调；
- 完成主要导航、项目切换、工作空间目录、对象搜索、预览和附件选择交互；
- 中间工作区和 Agent 面板先保留可替换占位；
- 不在一期实现真正的 Agent 调度、模型调用、流式输出、文件上传和对象持久化。

因此，PDF 中的“生成 PRD”“AI 场景分析”“对话修改对象”等能力，在本文档中会完整记录为产品需求，但会明确标注其当前实现状态为“未实现/后续阶段”，不会误判为当前项目已完成。

## 3. 功能清单与详细需求

## 3.1 模块一：用户登录与登出

### 模块目标

为用户提供进入平台、保持会话和退出平台的基础身份入口。F101 与 F104 是主链路 P0；F102 与 F103 属于登录增强能力，优先级为 P2。

### F101 账号密码登录

| 项目 | 详细要求 |
|---|---|
| 功能 ID | F101 |
| 功能名称 | 账号密码登录 |
| 优先级 | P0 |
| 入口 | 登录页面 |
| 用户动作 | 输入账号、密码，点击登录 |
| 系统行为 | 校验账号密码；成功后建立登录会话并进入主页面；失败时展示可理解的错误信息 |
| 成功结果 | 用户进入研发工作空间，默认显示工作台 |
| 异常情况 | 账号为空、密码为空、账号密码错误、后端不可用、请求超时 |
| 会话要求 | 登录成功后使用 HttpOnly Cookie；刷新页面仍保持登录 |
| 当前状态 | **已实现** |
| 当前实现证据 | `src/app/login/page.tsx`、`src/lib/api/client.ts`、后端 `/v1/auth/login` |
| 当前限制 | 使用 Demo 用户/认证链路；尚未接入正式用户数据库、权限角色和注册体系 |

**验收标准**

- 正确账号密码可以登录。
- 错误账号密码不会进入主页面，并显示错误提示。
- 登录成功后跳转到 `/`。
- 刷新主页面仍可通过 `/v1/auth/me` 恢复当前用户。
- Token 不写入浏览器可读存储。

### F102 “记住我”

| 项目 | 详细要求 |
|---|---|
| 功能 ID / 优先级 | F102 / P2 |

## 6. 非功能和实现约束

以下内容主要来自当前项目实施计划和代码规范，是实现上述功能时必须遵守的工程约束，不是 PDF 中新增的业务功能：

### 6.1 技术架构

- 前端使用 Next.js App Router + TypeScript。
- 页面组合放在 `src/components`，功能逻辑放在 `src/features`。
- API 请求集中在 `src/lib/api` 或对应 feature API 模块。
- Mock 数据放在 `src/mocks`，并应可替换为后端 API。
- 后端以 FastAPI/OpenAPI 为接口契约来源。
- 一期不引入 Redux、Zustand、XState、消息队列、工作流引擎或微前端。

### 6.2 认证安全

- 不将 Token 写入 `localStorage` 或 `sessionStorage`。
- 生产环境 Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Lax` 等安全策略。
- Demo 密码通过环境变量提供，不写入 Git。
- 正式用户、角色、权限、注册、找回密码和密码修改不能只用前端 Mock 冒充完成。

### 6.3 Agent 边界

一期只预留 Agent 面板和附件选择，不实现：

- Agent 调度；
- 中枢 Agent/Orchestrator；
- 专业子 Agent；
- 模型接入；
- 工具调用；
- SSE/WebSocket 流式响应；
- 会话和消息持久化。

后续建议以稳定的 Agent API、SSE 或 WebSocket 契约连接前端，不让前端依赖具体子 Agent 实现。

### 6.4 对象数据边界

正式实现对象能力前，需要至少确定：

- 对象类型和结构化 Schema；
- 对象唯一 ID、显示名称和编号规则；
- 对象版本、草稿、生成中、审阅中、已接受、已放弃等状态；
- PRD、UC、FR、FR 分配之间的关联；
- 对象删除、恢复、审计和权限规则；
- 文件对象与实际文件内容/存储的关系。
