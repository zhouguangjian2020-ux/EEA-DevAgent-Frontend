## 2. 产品运行时中枢 Agent 架构是否会影响当前方案

这里的“多 Agent 协同”指的是**产品运行时能力**，不是使用多个 Agent 来协同开发本项目：用户发起一次任务后，系统会调用一个中枢 Agent，由中枢 Agent 根据任务拆解、通信和调用其他专业 Agent，最后汇总结果返回给用户。

**结论：不会影响一期的前端和认证基础，但需要现在就把 Agent 作为独立的后端业务边界预留出来。** 一期不实现中枢 Agent 和子 Agent，只实现可替换的页面外壳、用户身份和文件附件交互。

### 对当前方案的调整

1. **前后端严格分目录、分职责**
   - `TS-frontend` 只放页面、组件、前端状态和 API Client。
   - `TS-backend` 只放 API、认证、业务服务和后端配置。
   - 前端不直接读取数据库，后端不返回面向页面的 HTML。

2. **OpenAPI 作为唯一接口契约**
   - 后端路由和 Pydantic Schema 生成 OpenAPI。
   - 前端从 OpenAPI 生成 TypeScript 类型和请求函数。
   - 生成目录禁止手工修改。

3. **为产品内 Agent 链路预留独立边界**
   - 建议未来位置：`TS-backend/app/modules/agent/`。
   - `orchestrator` 负责任务拆解、路由、调用子 Agent、重试、超时和汇总。
   - `agents` 负责各自专业能力，不直接操作前端页面。
   - 前端只依赖稳定的 `agent` API、SSE 或 WebSocket 契约，不依赖具体子 Agent 实现。

4. **一期只预留追踪字段，不引入复杂基础设施**
   - API 请求保留 `request_id`。
   - 异步 Agent 任务预留 `task_id`、`parent_task_id`、`status`、`progress` 和 `error`。
   - 一期不创建消息队列、工作流引擎或 Agent 注册中心。

5. **运行时调用链建议**

```text
用户
  ↓
Next.js 前端
  ↓ agent API
FastAPI
  ↓
中枢 Agent / Orchestrator
  ├─ 通信、拆解和调度
  ├─ 调用需求 Agent
  ├─ 调用架构 Agent
  ├─ 调用测试 Agent
  └─ 汇总结果
  ↓
SSE / WebSocket / 普通 JSON
  ↓
前端会话和工作区
```

### 未来建议的产品内 Agent 角色

| 角色 | 责任 | 一期是否实现 |
|---|---|---|
| 中枢 Agent / Orchestrator | 接收用户任务、拆解、调度、汇总 | 否 |
| 需求 Agent | PRD、场景、需求提取等专业任务 | 否 |
| 架构 Agent | 逻辑架构、物理架构等专业任务 | 否 |
| 开发 Agent | 代码或接口相关任务 | 否 |
| 测试 Agent | 测试用例、测试分析等任务 | 否 |
| 文件/知识 Agent | 文件检索、内容解析、上下文整理 | 否 |

一期只做这些能力的 UI 占位和附件选择，不提前假设子 Agent 的具体协议。

## 4. 代码和 Vibe Coding 约束

### 通用规则

- 先读 `AGENTS.md` 和本计划，再开始改代码。
- 一次只实现一个模块或一个明确交互。
- 每次改动后运行对应模块的验收命令。
- 不因为“以后可能会用”提前引入复杂框架。
- 不把截图当成 UI 背景，必须用真实 HTML/CSS/组件实现。
- 不把中间工作区和 Agent 业务提前做大。

### 前端规则

- 页面组合放在 `components`，跨页面业务状态放在 `features`。
- API 请求不能散落在展示组件中。
- Token 统一放在 `styles/tokens.css` 或 Tailwind theme。
- 不直接修改生成的 API 文件。
- 优先使用 React 本地状态；一期不引入 Redux/Zustand/XState。
- 组件命名使用 PascalCase，变量和函数使用 camelCase。
- 文件名使用 kebab-case。

### 后端规则

- 路由只负责 HTTP 层，业务逻辑放 service。
- 请求/响应模型统一放 schemas。
- 不在路由里直接写数据库逻辑。
- API 路径统一使用 `/v1` 前缀。
- 错误响应保持稳定结构。
- 密钥、密码和环境配置不写入 Git。

### 每个任务的完成定义

```text
代码完成
+ 类型检查通过
+ Lint 通过
+ 相关测试通过
+ 手动验收通过
+ 本计划进度已更新
+ 问题已记录或关闭
```
