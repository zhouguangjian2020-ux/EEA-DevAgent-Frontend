## 5. PRD流式实现与易错点

### 5.1 实际调用

```text
PRD标签页“生成 PRD”
→ POST /api/v1/agent/prd/generate/stream（Next同源代理，登录Cookie）
→ POST /v1/agent/prd/generate/stream（TS-backend）
→ 校验用户/项目/功能，读取项目名、功能名和已保存的功能描述
→ Agent /api/v1/agent/invoke/stream，scene=FROM_DEFINITION_CREATE_PRD
→ 上游NDJSON/SSE转成业务SSE token / done / error
→ 前端“生成预览（未保存）”
```

前端当前请求体：

```json
{"project_id":"项目UUID","function_id":"功能UUID"}
```

- 可选 `version`当前UI不传；不要用数据库revision_no充当文档版本，也不写死V1.0。
- 前端不传正文、项目名、功能描述或AgentKey；PRD生成依据是**功能定义**，不是已有PRD正文。
- 后端把功能定义放入消息/参考数据，`inputs.project`为真实项目名，`response_format=text`，无output schema。完整结构看34号和 `build_prd_generation_request`。
- 配置的Agent目标是 `http://192.168.64.3:8300/api/v1/agent/invoke/stream`；缓冲地址为 `/api/v1/agent/invoke`。不把地址当成DB/SSH授权。

SSE示意，每个事件后空一行：

```text
data: {"type":"token","content":"正文片段","request_id":"..."}

data: {"type":"done","scene":"FROM_DEFINITION_CREATE_PRD","output":"完整Markdown","request_id":"...","trace_id":"..."}
```

- `done.output`权威，**替换**累计预览，不重复追加。没有效done不能成功。
- `fetch + ReadableStream + TextDecoder`处理UTF-8和分块SSE，不是EventSource GET或完成后假打字。普通模式约80ms批量渲染；减少动态效果模式仅显示最终结果。
- HTTP/SSE错误、断流、场景错误、空输出、大小限制、超时/取消都有处理；旧回调按请求身份丢弃。

### 5.2 UI/存储边界

- 当前只接**已有数据库PRD标签页**；空功能直接生成并创建第一份PRD未接入。
- PRD生成要求已保存功能描述/编辑能力，**不要求PRD已确认**；UC生成才要求已确认来源PRD，不混淆两个按钮。
- 编辑/保存/确认或对象任务运行时禁止生成；防双击。生成中不允许原文写动作和生成UC。
- `PrdWork.prdGeneration`独立于 `session.document` / `editDraft` / 数据库版本；原PRD确认状态不改，预览不会继承“已确认”。
- 预览没有保存/确认/编辑/生成UC控件；切回原文保留既有手动流程，不要误删。
- 成功“已生成 PRD”禁用，是**当前内存预览的实现默认**，不是持久化的一次性生成政策。
- 停止/失败丢弃不完整预览，原文保留，恢复“生成 PRD”；不保证远端Agent推理同时停止。
- 切标签/项目不串结果；关闭运行中标签需“停止并关闭”。手动上滚不被新内容拉到底部；整页刷新会丢失预览，有明确提示。
