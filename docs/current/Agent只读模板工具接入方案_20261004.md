# Agent只读模板工具接入方案（2026-10-04）

状态：方案，尚未实施。用户询问如何注册业务接口为Agent工具。本轮仅核对本地/冻结源码并记录方案，不修改业务应用、注册Agent工具或连接公司服务。

## 1. 已核实的现状

已比对ts-backend-20261003-workflows-r2冻结归档和本地的app/api/routes/agent.py、app/services/uc_template.py、app/schemas/workflows.py、app/main.py，四个文件字节一致。

- 已有UC模板接口：GET /v1/agent/uc-template?scene=FROM_PRD_CREATE_UC。
- 公司主后端基址：http://192.168.64.3:7000，来自用户部署回执；本文未作实时远程验证。
- 鉴权header为X-Agent-Internal-Key，值匹配业务后端AGENT_CALLBACK_KEY。不使用浏览器登录Cookie。密钥未配置返回503，调用未提供或提供错误密钥返回401；响应含X-Request-ID。
- UC模板返回template_id=uc-default、template_version=1、fields、candidate_schema及instructions。模板静态定义，不访问业务数据库。
- candidate_schema由UcCandidateContent.model_json_schema()生成；说明生成信封使用structured.use_cases。number由后端保存时生成，Agent不得编造正式编号。
- 冻结包未发现FR模板路由。已有FR候选校验模型为FrCandidate，不能把规划中的FR模板路径说成已上线。

## 2. 第一版建议范围

| 工具名 | 固定HTTP映射 | 状态 |
|---|---|---|
| get_uc_template | GET /v1/agent/uc-template?scene=FROM_PRD_CREATE_UC | 复用已有接口，Agent侧注册待实现 |
| get_fr_template | GET /v1/agent/fr-template?scene=FROM_UC_CREATE_FR | 拟新增接口，当前不可调用 |

工具第一版建议无模型入参，只接受空对象并拒绝额外字段。执行器固定path/scene/HTTP方法；模型不能传入URL、密钥或任意header。基址、回调凭证只放Agent服务端配置，不放前端或工具定义中。

不把整个业务OpenAPI全部注册给模型；不注册任意HTTP、任意SQL、保存或确认操作。获取业务PRD/UC对象属于另一种受用户/项目/版本授权约束的读取能力，不能因有模板服务密钥就允许任意读取。

## 3. 双向鉴权不可混用

| 方向 | header | 业务后端中的对应配置 |
|---|---|---|
| 业务后端调用Agent | X-API-Key | AGENT_API_KEY |
| Agent调用业务后端模板 | X-Agent-Internal-Key | AGENT_CALLBACK_KEY |

Agent执行器持有的回调密钥应与后端AGENT_CALLBACK_KEY匹配，通过私密配置渠道交付。不打印、不贴聊天、不写入模型参数或日志。只在批准的内网边界访问；跨非可信网络应先保护传输，而不是直接复用当前明文HTTP连接。

## 4. Agent工程师负责工具注册和执行

1. 为get_uc_template/get_fr_template定义用途说明、空对象入参schema与实际执行函数。仅把URL写进提示词、或把工具名字告诉模型，不等于运行时已能调用接口。
2. 执行函数调用固定GET地址，由服务端附加X-Agent-Internal-Key。设置超时，限制重定向，检查HTTP状态与返回JSON结构，防止凭证被转发到非预期地址。
3. 成功结果须作为本次Agent运行的tool result或上下文供模型使用，不能只记日志。错误不能转成空模板或让模型编造模板。
4. 若要求每次生成前必取模板，建议将取模板/核对版本作为明确的流程前置步骤，而非只靠模型自行决定是否调用。
5. 模型基于模板和本轮业务上下文生成候选，再交回原有后端校验及人工预览/采纳/确认；工具本身不保存业务对象。

第一版建议复用Agent现有函数/HTTP工具机制，不额外新增一个通用工具注册中心。若其已有MCP，则用MCP适配层暴露相同两项白名单工具；当前没有确认其框架，不提供假定可直接导入的注册JSON。

## 6. 观测与验收

Agent记录父生成请求的trace/idempotency key、tool_call_id、工具名、耗时、HTTP状态、模板ID/版本、后端响应X-Request-ID；必要时关联thread_id。不得把trace_id、idempotency_key或thread_id混为同一个标识。可以展示非敏感模板响应；凭证header须脱敏。新增工具日志不等于现有7200联调台自动能显示，展示接入另行验证。

本地验收：有效密钥成功；缺失/错误密钥拒绝；超时/非JSON/版本不符可见；返回schema与现有候选校验一致；真实工具结果进入模型上下文；生成符合契约；取模板无业务写入，不自动保存/确认。

本地开发和自动化检查→用户本地体验验收→修正与复测→再准备公司发布。不得借此自动升级线上、打开预览写开关或初始化其他数据。

模板是结构，PRD/UC正文是业务上下文；注册模板工具不会自动修复当前附件未被Agent使用的问题，仍须按已有请求定位两条链路。
