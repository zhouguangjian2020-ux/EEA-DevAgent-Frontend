# UC 接口：Agent 工程师本地命令行测试手册

日期：2026-10-01。适用后端：`ts-agent-backend:20260930-uc-r2`；公司前端已更新到 `20261001-uc-r3`。

## 0. 目的、完成状态与边界

本手册用于验证**我们提供的业务后端服务**，并帮助 Agent 工程师在本地开发 UC Skill。Skill 尚未完成时，不要求生成接口返回真实 UC 来证明健康接口和登录正常；但也不把一个 502 当作完整业务验收通过。

| 内容 | 截至本次交接的状态 |
|---|---|
| UC 生成、UC 模板查询、UC 图三个接口 | 已实现，已随 r2 后端部署；本地契约/模拟测试通过 |
| 前端部署、HTTP UUID 兼容性 | 用户已完成 r3 部署并成功确认 PRD |
| 公司后端健康、登录与会话 | 用户已提供成功回执 |
| 后端读取已确认 PRD 并向 Agent 发请求 | 已走到上游响应；发送结构另有本地 Mock 验证，不是线上完整正文抓包验收 |
| 当前 Agent Key / 场景查询 | 能力查询 HTTP 200；两个 UC 场景已注册，均配置为 `text` |
| 真正的 Agent UC 生成 | Skill 未完成；后端要求 `json` 与场景的 `text` 不一致，上游访问日志记录 HTTP 409 |
| 模板查询的公司现场成功回执 | 尚未取得，按步骤 4 补测；必须有独立模板凭证 |
| UC 图的公司现场结果、变化/未变化分支 | 尚未取得，按步骤 6～7 补测 |
| 完整 Agent Skill、生成质量、模板工具调用 | Agent 侧后续实现并联调，不属于已经完成的结果 |
| UC 图前端图形渲染 | 按约定暂缓；现阶段只做图代码/状态展示 |

**本包不部署、不改配置、不操作公司数据库、不创建/保存/确认/删除业务对象。** 两个 POST 生成接口只产生临时结果；未来真正接通 Skill 后会触发 Agent/模型调用，可能产生推理费用，不要循环重试。

## 1. 文件和准备条件

把本包解压到自己的电脑，进入包含 `README.md` 的目录，下面所有命令都在该目录执行，不依赖原作者电脑的 E 盘路径。

- `probe_uc_service.py`：健康、登录会话、模板查询，以及显式指定的本地 Agent 样例请求。
- `simulate_uc_requests.py`：原业务后端登录态模拟脚本；UC 生成和 UC 图要**分开运行**，因为前一个失败会使脚本退出。
- `requirements.txt`：只需要 `httpx==0.28.1`；Python 3.10 或更新版本。
- `examples/`：浏览器请求模板、两个 Agent 出站请求与期望响应、UC 模板快照。
- `validation-summary.json`：交接时的本地验证与现场边界。
- `SHA256SUMS`：包内文件校验值。

前提：电脑能通过公司网络/VPN访问 `192.168.64.3:7000`。这些是内网 HTTP 地址，只在可信公司网络使用，不要公开映射端口。

需向项目负责人安全领取：

1. 能访问测试项目的登录账号与密码。本次现场使用 `engineer01`，不是任何人都默认有该权限。
2. 模板专用 `AGENT_CALLBACK_KEY`。此值已在业务后端配置，但还没有确认已同步到 Agent 工程师。请通过公司认可的安全渠道提供，**不要贴到聊天、工单、Git 或本测试包**。
3. 本地 Agent 的 API Key 由工程师自己的 Agent 配置决定；并不要求与公司 Agent 的 Key 相同。

三种凭证不要混用：

| 调用方向 | 身份/请求头 |
|---|---|
| 命令行模拟前端 → 业务后端 | 登录账号密码 → 自动复用 HttpOnly `ts_session` Cookie |
| 业务后端 → Agent | `X-API-Key: <AGENT_API_KEY>`，不加 `Bearer ` 前缀 |
| Agent → 业务后端 UC 模板 | `X-Agent-Internal-Key: <AGENT_CALLBACK_KEY>`，不需要用户登录 Cookie |

所有密码/Key均隐藏输入；本包没有凭据。不要使用 `curl -v` 或公开完整 Cookie/请求头日志。生成结果可能包含业务内容，也不要公开原始结果。

## 3. 不依赖 Skill 的检查：健康和登录

Windows PowerShell：

```powershell
& $Python .\probe_uc_service.py health
& $Python .\probe_uc_service.py session --username engineer01
```

Linux / macOS：

```bash
"$PYTHON" probe_uc_service.py health
"$PYTHON" probe_uc_service.py session --username engineer01
```

预期：

```text
HEALTH_HTTP_STATUS=200
HEALTH_OK
LOGIN_HTTP_STATUS=200
SESSION_HTTP_STATUS=200
SESSION_OK
```

密码提示输入的是**用户登录密码**。脚本依次执行 `POST /v1/auth/login`、`GET /v1/auth/me`，同一客户端自动保留 Cookie，不输出或保存 Cookie 文件。

`/health` 只证明进程存活；登录验证认证链路，不等于全部数据库/Agent业务均通过。也可单独检查前端代理：

```powershell
& $Python .\probe_uc_service.py health --base-url http://192.168.64.3:7100/api
```

Bash把 `& $Python .\probe_uc_service.py` 换为 `"$PYTHON" probe_uc_service.py` 即可。

## 4. 不依赖 Skill 的检查：Agent 查询 UC 模板

Windows：

```powershell
& $Python .\probe_uc_service.py template --show-template
```

Linux / macOS：

```bash
"$PYTHON" probe_uc_service.py template --show-template
```

隐藏输入提示为 `AGENT_CALLBACK_KEY`。不要输入用户登录密码或 `AGENT_API_KEY`。

该命令实际请求：

```http
GET /v1/agent/uc-template?scene=FROM_PRD_CREATE_UC
X-Agent-Internal-Key: <独立模板凭证>
Accept: application/json
```

预期：

```text
UC_TEMPLATE_HTTP_STATUS=200
UC_TEMPLATE_OK formal_fields=12 candidate_fields=11
UC_TEMPLATE_RESPONSE
...模板 JSON...
```

此步骤直接测试业务后端，**无需 UC Skill 开发完成**。若未拿到凭证，登记“待测”，不要拿其他 Key 试到成功为止。401 通常检查模板凭证；503 `agent_template_not_configured` 表示业务后端缺少该配置，交由负责人处理。

模板约定：正式 UC 12 个顶层字段：

```text
name, description, number, actors, preconditions, scenario,
postconditions, extensions, hmi, regulations, performance, nonfunctional
```

其中 `scenario` 是对象：`main_flow: string`、`branches: string[]`、`exceptions: string[]`。不是 14 个平铺字段。分支/异常数量由 PRD 决定，可为 `[]`，不强制 4/5 条。

Agent 候选只返回除 `number` 外的 11 个字段；不返回 `candidate_id`、`ordinal`、正式对象/版本 ID。编号由后端正式保存时生成。`candidate_schema` 只是业务接口契约，不要求在 Agent Skill 中新增 `output.schema` 配置。

## 6. 单独测试 UC 图请求

保留步骤 5 的地址、账号、项目、功能环境变量，但关闭 UC 生成，避免它失败后阻断图接口测试。

Windows：

```powershell
$env:UC_RUN_GENERATION = '0'
$env:UC_RUN_DIAGRAM = '1'
Remove-Item Env:UC_KNOWN_UC_SOURCE_VERSION -ErrorAction SilentlyContinue
& $Python .\simulate_uc_requests.py
```

Linux / macOS：

```bash
export UC_RUN_GENERATION=0 UC_RUN_DIAGRAM=1
unset UC_KNOWN_UC_SOURCE_VERSION
"$PYTHON" simulate_uc_requests.py
```

实际接口：`POST /v1/agent/uc-diagram`。请求字段为 `scene=FROM_UC_CREATE_UC_DIAGRAM`、`project_id`、`function_id`、`client_request_id`、`known_uc_source_version`。**不由前端提供 UC 列表。** 后端读取本功能下所有有效的已确认 UC版本，草稿不进入图输入；数量超过实现上限100时显式拒绝，不偷偷截断。

可能结果：

- HTTP 200，`status=empty`：本功能没有有效已确认 UC，**不会调用 Agent**。这是正确的空集合行为，不等于图生成已测通。
- 有已确认 UC且需生成：会调用 Agent。目前其 `text` 配置可能再次导致上游拒绝，记为依赖未就绪；现场尚无这条链路成功回执。
- Skill 接好后：HTTP 200，`status=succeeded`，返回 `source_version`、`source.uc_count`、`diagram_format`、`diagram_code`。

UC 生成接口返回的候选并不自动成为已确认 UC。因此刚运行生成接口，图接口仍然 `empty`，不一定是缺陷。应由负责人选用已有已确认 UC 的测试功能，或通过既有人工流程准备测试数据；本包不代为保存/确认。

## 7. UC 图未变化短路测试（拿到真实来源版本以后）

在前一次 `succeeded` 响应中取 `source_version`（64位小写十六进制）。保持已确认 UC 集合和版本不变，然后：

Windows：

```powershell
$env:UC_KNOWN_UC_SOURCE_VERSION = '<替换为上次响应的source_version>'
& $Python .\simulate_uc_requests.py
```

Linux / macOS：

```bash
export UC_KNOWN_UC_SOURCE_VERSION='<替换为上次响应的source_version>'
"$PYTHON" simulate_uc_requests.py
```

仍保持 `UC_RUN_GENERATION=0`、`UC_RUN_DIAGRAM=1`。不要把占位文字原样执行。

预期 `status=unchanged`，不调用 Agent，也不重新返回/生成旧图；前端使用自己缓存的图。数据库不新增图持久化表。若来源仍是空集合，按当前实现优先返回 `empty`，不是 `unchanged`。

验证“未调用 Agent”应结合本次请求时间/trace与受控调用计数或安全访问日志；仅 HTTP 200 不能替代调用次数证据。不要为测试自动修改公司 UC；后续变化分支由负责人准备新的已确认测试版本，再确认 `source_version` 改变并触发生成。

## 8. 工程师自己的本地 Skill 如何测试

**关键拓扑：从本机调用公司7000端口，业务后端仍然调用它当前配置的公司8300端口。不会自动调用你本机的8300。** `UC_API_BASE_URL` 是业务后端地址，不是 Agent 目标地址。

先在本地 Agent 使用本包的合成出站样例，模拟“业务后端 → Agent”：

Windows（分别执行，Key隐藏输入）：

```powershell
& $Python .\probe_uc_service.py agent-local --agent-url http://127.0.0.1:8300/api/v1/agent/invoke --request-file .\examples\uc-agent-generation.outbound.example.json
& $Python .\probe_uc_service.py agent-local --agent-url http://127.0.0.1:8300/api/v1/agent/invoke --request-file .\examples\uc-agent-diagram.outbound.example.json
```

Linux / macOS：

```bash
"$PYTHON" probe_uc_service.py agent-local --agent-url http://127.0.0.1:8300/api/v1/agent/invoke --request-file examples/uc-agent-generation.outbound.example.json
"$PYTHON" probe_uc_service.py agent-local --agent-url http://127.0.0.1:8300/api/v1/agent/invoke --request-file examples/uc-agent-diagram.outbound.example.json
```

`agent-local` 为避免误调用公司环境，仅允许 `localhost` / `127.0.0.1` / `::1`，使用独立隐藏输入的本地 Agent API Key，自动更新样例幂等标识和 trace_id。这一步可能真正调用模型，仅在本地实现就绪后执行；返回 HTTP 200 仍需对照期望响应检查字段，辅助脚本不冒充完整契约验收器。

UC Skill还需要在自己的实现/配置里设定：

- 业务后端基地址：`http://192.168.64.3:7000`；
- 模板路径来自请求中的 `reference_data.uc_template.path`；
- 模板凭证通过安全配置读取，发送 `X-Agent-Internal-Key`。

这里描述的是配置要求，不假设你的 Agent 已支持某个特定环境变量名；本包不会替你改 Agent 配置。后端不会在 PRD请求中透传模板密钥。

本地成功后，由项目负责人协调部署 Skill 或使用独立测试后端指向工程师可达的 Agent，再复测步骤 5～7。不要为了本地调试擅自把当前公司后端目标改成 `127.0.0.1`、开放本机端口到公网或修改业务数据库。

## 9. 两个 Skill 的输入输出契约

### 9.1 UC 生成

- `scene=FROM_PRD_CREATE_UC`，`response_format=json`。
- 完整输入在 `reference_data.prd_markdown`，来源身份在 `reference_data.source`。
- 按模板生成 JSON对象 `{"use_cases":[...]}`；服务封套中放入 `structured`，并保留正确 `scene` 和 `trace_id`。
- 每个候选 11 个字段，`scenario` 中主流程/分支/异常嵌套；不返回编号或多余字段。字段需完整；不明确事实标记 `<待确认>` / `<待标定>`，不要编造。
- 后端也兼容外层 `output` 字符串包含同一份**纯 JSON**；不接受 Markdown/代码围栏/说明文字冒充结构化结果。
- 候选数量1～100；分支/异常各0～100项；更多约束以模板 `candidate_schema` 为准。
- 期望响应：`examples/uc-agent-generation.response.example.json`。

### 9.2 UC 图

- `scene=FROM_UC_CREATE_UC_DIAGRAM`，`response_format=json`。
- 输入为 `reference_data.uc_list` 中的已确认 UC完整内容和对象/版本标识；`reference_data.uc_source_version` 是后端来源指纹。
- 返回 JSON对象只含 `diagram_format`、`diagram_code`，封装到 `structured`；不修改来源 UC。
- **现有桥接代码暂时要求 `diagram_format=mermaid`**，但图形渲染与最终图格式按产品约定仍待 Agent 对齐。若最终不用 Mermaid，应双方统一修改契约，而不是单方更换字符串。
- 期望响应：`examples/uc-agent-diagram.response.example.json`。

### 9.3 避免无效对接

- 业务后端目前没有给 UC 场景发送额外 `inputs`，完整资料在 `reference_data`。若你的 Skill强制必填 `inputs`，需要 Agent侧适配或双方明确修改输入契约，不能假设 `message` 自动补齐。
- 当前现网两个场景都声明 `text`；建议开发完成时对齐结构化 JSON。只修改场景配置还不够：对应 Skill 的输出声明和实际输出需一致，本地 Agent 源码会在加载时校验这些配置。不要直接对现网全局替换 `text`，以免破坏已有 PRD 场景。
- Skill内部格式与外层 HTTP JSON封套不是一回事；`Content-Type: application/json` 不意味着 Skill 已输出结构化 UC。
- 若遇到参考资料大小限制，双方核对实际限制；不能通过截断完整 PRD/丢弃 UC来伪造成功。
- 不要把样例中的合成UUID、全零来源版本和示例UC编号当作公司真实身份。样例只用于本地 Agent；调用公司业务后端使用步骤5的真实身份。

## 10. 常见结果与交回的验收记录

| 结果 | 处理 |
|---|---|
| 连接失败/超时 | 先检查公司网络/VPN、目标端口与服务；别改业务数据 |
