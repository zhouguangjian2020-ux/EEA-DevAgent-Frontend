## 2. 测试方法与实际接口声明

请求接口：

```text
POST http://192.168.64.3:8300/api/v1/agent/invoke/stream
Content-Type: application/json
Accept: text/event-stream
X-API-Key: <从本地业务后端私密配置读取，不写入报告>
```

每次请求体严格只有用户指定的两个字段：

```json
{"message": "帮我给AEB进行定义", "scene": "FEATURE_DEFINITION"}
```

- 10次串行独立请求，不传thread_id/inputs/模型参数/输出格式参数；没有对message追加JSON格式指令，没有复用会话。实际返回10个不同thread_id和10个不同task_id。
- 不自动重试，不以额外调用替换失败样本；第6组空输出按原样记入结果。
- 收到终态done/error/interrupt即停止消费流；本批10次终态均为done。
- 响应Content-Type均为`text/event-stream; charset=utf-8`，实际为逐行JSON（NDJSON），不是要求`data:`前缀的标准SSE帧。
- 开始：`2026-09-22T20:35:24.777807+08:00`；结束：`2026-09-22T20:36:06.679612+08:00`。

实际GET `/api/v1/agent/capabilities`返回的场景声明：

```json
{
  "scene": "FEATURE_DEFINITION",
  "description": "定义完整功能说明（50~100字）",
  "response_format": "text",
  "timeout_seconds": 120
}
```

能力清单中的`product_agent.feature_definition`技能版本为`1.0.0`，output.format为`plain_text`；说明要求一段50～100字正文，不要标题、编号、分点或解释。**因此当前目标本来就是短功能说明，并不是完整PRD或结构化功能对象。**

OpenAPI中流式接口200响应的schema是空对象`{}`，没有声明本场景正文的必填业务字段。非流式InvokeResponse虽有可选structured字段，也不能据此认为当前流式接口会提供它。不能仅因scene相同或样本字段一致，就承诺以后一定满足同一业务schema。

## 4. 外层返回究竟稳定到了什么程度

9组有正文的响应都包含若干token事件，字段为：

```json
{"type": "token", "content": "正文片段"}
```

10组终态事件都具有以下6个字段，值的类型全部为string（ID随请求变化）：

```json
{
  "type": "done",
  "task_id": "本次任务ID",
  "thread_id": "本次会话ID",
  "trace_id": "本次追踪ID",
  "scene": "FEATURE_DEFINITION",
  "output": "一段功能说明；本批有一次为空字符串"
}
```

可依赖的**本次观察**：外层字段名/类型相同，scene值均正确。不能从这10次推导整个事件序列固定：token数量会变化，第6组甚至没有任何token。正常分支一致也不代表错误/中断分支相同；本批没有覆盖错误码、超时、中断、重启或模型更新。

不可依赖的推断：output一定非空、一定50～100字符、一定包含可单独解析的功能名称/场景/能力/价值等字段。后者目前只是自然语言内容，没有分字段结构。

## 6. 最小接入建议（尚未实施）

1. 如果业务只要“功能说明正文”，继续用文本，不为此新增数据库表或通用结构解析层。业务后端检查HTTP状态、终态、scene、output类型及非空；只有通过检查才回填。
2. 空字符串按失败处理，保留用户原输入，显示可重试提示；不能仅凭HTTP 200/done就覆盖草稿。本批不自动重试，以免掩盖真实失败。
3. 若50～100字符是硬性规则，让Agent端生成后校验，超限明确报错或按已确认规则修正，不在前端静默截断。
4. 如果真正需要“名称、定义、适用场景、主要能力、边界”等稳定字段，需要先确定必填/可选字段和类型，再由Agent或业务后端实施schema校验；仅固定scene或要求模型“尽量输出JSON”不等于强约束。本轮没有新增这些字段。
5. 保留请求追踪标识以定位第6组；不要把内部密钥或上游原始认证信息带到浏览器。

**本轮没有把现有自动扩写按钮的ONE_CLICK_EXPAND替换为FEATURE_DEFINITION。** 这是对用户指定新scene的直接测试，不是新功能已接入的声明。
