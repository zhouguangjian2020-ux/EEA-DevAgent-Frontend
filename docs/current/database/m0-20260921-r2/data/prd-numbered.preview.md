1 文档说明

1.1 概述

本文档定义行车记录仪（Digital Video Recorder，简称DVR）功能的产品需求，包括功能范围、用户场景、功能需求、验收标准等内容，作为研发、测试、设计的参考依据。

2 需求背景

2.1 产品价值/目的

行车记录仪作为智能网联汽车的安全标配配置，通过摄像头实时记录车辆行驶过程中的视频画面、声音等信息，为交通事故责任判定提供客观、可靠的证据支持，同时在停车场景下提供全天候的车辆安全监控服务，并支持用户记录沿途风景、剪辑精彩视频。

核心价值：

| 价值维度 | 说明 | 用户感知 |
| --- | --- | --- |
| 安全价值 | 提供客观的事故证据链，有效保护驾驶员合法权益；停车监控功能可在车辆受到碰撞或异常移动时自动记录关键证据，协助事故调查和保险理赔 | 事故有据可查，停车有人守护 |
| 便捷价值 | 支持语音快捷拍照、视频快速回放、紧急事件一键锁定等功能，便于用户快速获取所需内容 | 操作简便，随用随取 |
| 娱乐价值 | 支持沿途风景随手拍、AI智能识别精彩瞬间、类剪映式视频剪辑，让用户在旅途中记录美好、创作专属回忆 | 边开边拍，一键出片 |
| 法规价值 | 满足国家对于汽车行驶记录仪的法规要求 | 合规无忧 |
| 产品竞争力 | 1080P高清录制、停车监控、APP远程查看等功能已成为用户购车决策的重要考虑因素 | 购车加分项 |

3 需求描述

3.1 应用场景

站在驾驶员视角，描述用户可感知、可操作的功能价值、体验与结果。

概述：

行车记录仪功能贯穿用户用车的全场景生命周期，从日常通勤的自动录制，到突发事故的紧急锁定，再到停车期间的持续监控，为用户提供全天候、无感知的安全保障体验；同时支持沿途风景记录和视频剪辑，让每一次出行都能留下美好回忆。

📌 安全类场景：

| 场景编号 | 场景描述 |
| --- | --- |
| 场景1 | 日常通勤：车辆启动后自动开始录制，用户无需任何操作，录制指示灯亮起提示 |
| 场景2 | 交通事故：发生碰撞时系统自动检测到异常振动，系统锁定当前及前后各30秒视频 |
| 场景3 | 紧急取证：用户发现前方异常情况，快速点击锁定按钮，当前视频被永久保护 |
| 场景4 | 停车监控：熄火后进入停车监控模式，检测到异常振动时自动录像；高风险事件时第一时间向用户推送通知 |
| 场景5 | 视频回放：需要查看历史视频时，用户按时间轴浏览或按类型筛选 |
| 场景6 | 证据导出：用户通过APP或USB导出需要的视频片段 |
| 场景7 | 隐私保护：用户可选择关闭录音功能，仅录制画面，保护车内隐私 |

📌 娱乐类场景：

| 场景编号 | 场景描述 | 用户价值 |
| --- | --- | --- |
| 场景8 | 沿途风景：驾驶途中说出"抓拍照片"指令，系统截取当前画面保存到相册 | 不错过任何美景 |
| 场景9 | 精彩瞬间标记：行驶途中遇到美景/有趣场景，语音说"标记精彩瞬间"，系统自动标记前后片段供后续剪辑 | 智能标记，素材不遗漏 |
| 场景10 | AI自动剪辑：行程结束后，系统自动识别精彩片段（风景、弯道、加速等），生成15-60秒精华视频 | 一键出片，懒人友好 |
| 场景11 | 旅行Vlog制作：用户可进入剪辑模式，对标记的精彩片段进行裁剪、拼接、配乐，生成专属旅行视频 | 创意表达，个性定制 |
| 场景12 | 社交分享：剪辑完成的视频可一键分享到微信、抖音等社交平台 | 分享快乐，收获点赞 |

3.2 功能定义

功能概述：

行车记录仪功能是一套完整的车辆行驶过程记录与回放系统，通过摄像头实时采集车辆前方画面（1080P@30fps），支持车内麦克风采集声音，在中控屏和手机APP上提供视频预览、回放、导出等操作界面，为用户提供安全行车记录和停车监控服务。娱乐功能（精彩瞬间捕捉、视频剪辑）为增值功能，高清娱乐版标配。

功能运行简介：

| Plaintext<br>车辆上电 → 系统自检 →摄像头激活 → 开始循环录制<br>    ↓<br>振动监测中 → 检测到异常振动 → 自动锁定当前视频<br>    ↓<br>用户操作 → 语音/触控拍照 → 保存图片到相册<br>    ↓<br>用户请求 → 视频回放 → 时间轴导航 → 选择播放/导出<br>    ↓<br>车辆下电 → 进入停车监控模式 → 持续监测振动信号<br>    ↓<br>检测到异常 → 自动录像并锁定 → 高风险事件通知用户 → 用户返回后查看 |
| --- |

5 验收指标

5.1 主观指标

说明：以下验收标准以产品负责人（PO）的视角，从用户主观感受出发描述各项功能应达到的体验水平，供评审和验收参考。

📌 安全类验收标准：

| 验收项 | 验收标准（PO视角） | 验收说明 |
| --- | --- | --- |
| 录制状态可辨识度 | 驾驶员在驾驶时，无需刻意关注，只需余光扫一眼就能判断行车记录仪是否在正常工作 | 状态图标应足够醒目，颜色和位置符合用户直觉 |
| 紧急锁定体验 | 当发生碰撞时，系统能迅速锁定视频，驾驶员会感到"关键时刻可靠" | 锁定应有明显的视觉和听觉反馈，让用户确信重要视频已被保护 |
| 语音交互体验 | 日常普通话指令能准确识别并快速响应，驾驶员感觉"说话就能用" | 不需要刻意放慢语速或提高音量，像和助手说话一样自然 |
| 界面操作流畅度 | 浏览视频列表、切换画面时流畅自然，不会让人感觉"卡顿"或"迟钝" | 操作体验应与主流APP看齐，滑动和点击响应及时 |
| 停车监控安心感 | 停车后车辆被意外触碰时，能及时感知并收到通知，心里踏实 | 不需要频繁检查，信任系统会守护车辆安全 |
| 夜间录制效果 | 夜间或光线不足时，录制的视频仍能清楚记录前方情况 | 用户拿到视频后能看清关键信息，不会说"什么都看不清" |
| 恶劣天气适应性 | 雨、雪、强光、逆光、雾霾等恶劣天气下，视频仍能记录前方情况，不会出现"白茫茫一片"或"什么都看不清" | 用户在雨天、雪天、隧道进出、大雾等场景下，对记录效果感到可用 |
| 事件通知及时性 | 停车期间发生异常时，手机能及时收到通知，不会"事后才知道" | 通知应简洁明确，让用户快速判断事件严重程度 |

📌 娱乐类验收标准：

| 验收项 | 验收标准（PO视角） | 验收说明 |
| --- | --- | --- |
| 标记操作即时感 | 说"标记精彩瞬间"后，系统反应迅速，不会让人觉得"没反应" | 操作反馈应及时，让用户确信标记成功 |
| AI推荐实用性 | AI推荐的精彩片段，用户会觉得"确实不错"而不是"这是什么" | 推荐应精准，减少用户筛选成本 |
| AI快剪惊喜感 | 行程结束后生成的精华视频，让用户有"哇，居然剪得还不错"的惊喜 | 剪辑质量应超出用户预期，产生分享欲望 |
| 剪辑操作流畅度 | 手动剪辑时，手指滑动、拖拽流畅自然，像在手机上剪辑一样顺手 | 不应出现明显的延迟或操作跟不上的情况 |
| 导出视频质量 | 导出的视频在手机上播放清晰，分享到社交平台后不会模糊失真 | 用户自己愿意把视频分享出去，不会觉得丢脸 |
| 分享成功率 | 一键分享操作简单直观，不会莫名其妙地失败或出错 | 用户觉得"点一下就发出去了"，而不是需要反复操作 |

| 指标 | 类别 | 标准值 | 说明 |

| 紧急锁定响应时间 | 安全类 | ≤2秒 | 从异常检测到视频锁定的延迟 |
