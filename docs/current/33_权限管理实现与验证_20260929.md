# 权限管理实现与验证（2026-09-29）

## 1. 用户确认的精简范围

- 项目级角色：项目管理员、项目查看者。
- 功能级角色：功能查看者、功能编辑者；工程审查和确认并入功能编辑者，不单独设置功能审核者。
- 权限只作用于当前项目；功能级权限只作用于当前项目内指定功能。
- 第一版只配置允许能力，不做显式拒绝规则、自由权限矩阵、SSO/LDAP/OIDC、找回密码或复杂组织架构。
- 只有项目管理员可以打开和修改当前项目权限设置；全局账号管理由部署配置的账号管理员 subject 控制。
- 创建账号后可以登录，但默认不加入任何项目，也没有任何项目/功能权限。
- 既有删除依赖保护仍然有效，权限不会绕过删除规则。

## 2. 已实现的后端

新增/修改的主要文件：

- `app/core/security.py`、`app/core/config.py`、`app/api/routes/auth.py`、`app/schemas/auth.py`、`app/services/identity.py`：数据库账号登录、停用账号拒绝登录、真实 subject 传递、账号管理员能力字段。
- `app/services/business_access.py`：项目级权限继承、指定功能级权限计算和范围隔离。
- `app/services/permission_admin.py`、`app/services/account_admin.py`、`app/api/routes/permissions.py`、`app/schemas/permissions.py`：账号、成员和功能授权 API。
- `app/services/metadata_edit.py`、`app/services/manual_work.py`、`app/services/deletion.py`、`app/services/bulk_deletion.py`：现有写入/确认/删除请求按项目和功能权限重新校验。
- `app/services/projects.py`、`app/schemas/projects.py`：项目列表返回 `can_manage_access`，前端据此控制入口。

接口范围：

```text
GET    /v1/accounts
POST   /v1/accounts
PATCH  /v1/accounts/{user_id}
GET    /v1/projects/{project_id}/permissions
GET    /v1/projects/{project_id}/permission-candidates
POST   /v1/projects/{project_id}/members
DELETE /v1/projects/{project_id}/members/{user_id}
POST   /v1/projects/{project_id}/functions/{function_id}/permissions
DELETE /v1/projects/{project_id}/functions/{function_id}/permissions/{user_id}
```

写请求仍要求 HttpOnly session、允许的 Origin、`X-Project-Request: 1` 和 JSON Content-Type；接口不返回密码或密码 hash。移出项目会撤销该项目的功能级绑定；功能权限撤销后按项目角色回退。

## 3. 已实现的前端

- 顶部当前项目显示“项目权限”，只在 `can_manage_access=true` 时出现。
- 弹窗包含“项目成员”和“功能权限”两个标签；成员可加入已有账号、选择项目角色、调整角色和移出；功能页按功能选择成员的功能角色。
- 账户菜单显示“账号管理”时使用当前用户的 `can_manage_accounts`；账号页可创建、启用/停用账号，密码只在表单提交时存在，不在列表中显示。
- Mock 模式保留可交互演示数据；真实模式不会在后端写入不可用时伪装为 Mock 成功。
- 沿用现有前端 token、modal、table 和语义色，不新增全局状态库或复杂权限矩阵。

## 4. 数据库增量包

目录：`docs/current/database/permission-admin-20260929`

- `inspect.sql`：只读检查。
- `apply.sql`：创建账号凭据表、放开 function scope、添加固定功能角色/能力、补最小 writer/reader 授权。
- `assertions.sql`、`verify.sql`：结构、角色、能力、唯一索引、外键和授权断言。
- `rollback.sql`：没有账号和功能绑定时才允许回退；不删除业务历史、审计和业务对象。
- `target.sql`：数据库名、cluster system identifier、PostgreSQL 18、R2 migration fingerprint、owner 和 superuser 闸门。
- `render_sql.py`、`SHA256SUMS`：现场渲染前完整性校验，不连接数据库、不读取密码。

公司数据库边界：助手没有连接公司数据库、SSH、重启服务或写入公司账号。数据库包只提供给用户/DBA在停写、备份、现场审查后执行。执行完成也不等于应用已经部署，需要再配置后端 ro/rw DSN、业务写开关和账号管理员 subject，并进行真实登录和权限验收。
