# 38 UC接口实现与联调说明（2026-09-30）

## 1. 本轮目标与边界

本轮把 UC 生成、UC 图生成所需的业务后端桥接接口补齐，并为后续 Agent skill 工程提供稳定、可核对的输入/输出契约。**不修改 Agent 工程，不连接公司数据库，不 SSH，不执行公司迁移或部署。**

已确认的产品边界：

- UC 生成结果只作为候选展示；本轮不会自动创建正式 UC，也不会自动确认。
- UC 仍是 12 个顶层字段；“场景”是其中一个顶层字段，内部包含主事件流、分支事件流、异常事件流。
- 分支和异常都是可变长度数组；不强制 4 个分支或 5 个异常，也不为了填槽位编造内容。
- UC 正式编号由业务后端在正式保存时生成；Agent 候选不返回正式编号、对象 ID 或版本 ID。
- UC 图接口暂定返回 Mermaid 代码；数据库模式前端已接入 UC 文件夹打开/全景刷新触发、状态处理和安全文本预览，但 Mermaid 图形渲染仍暂缓，等 Agent 场景输出稳定后再接入。
- UC 图使用 `known_uc_source_version` 指纹判断是否变化；未变化不调用 Agent；第一版不新增图持久化表。

## 2. UC 正确结构

### 2.1 正式 UC 的 12 个顶层字段

```text
1. name            用例名称
2. description     用例描述
3. number          用例编号（正式保存时由后端生成）
4. actors          参与者
5. preconditions   前置条件
6. scenario        场景
7. postconditions  后置条件
8. extensions      扩展用例
9. hmi             HMI交互逻辑
10. regulations    法规需求
11. performance    性能需求
12. nonfunctional  非功能需求
```

### 2.2 Agent 候选的 JSON 结构

候选响应不带 `number`，因此传输时是 11 个内容字段；这不是少了一个正式字段，而是把后端生成的正式编号留在保存边界之外。

```json
{
  "name": "记录事件",
  "description": "系统记录事件。",
  "actors": "驾驶员；系统",
  "preconditions": "设备已上电。",
  "scenario": {
    "main_flow": "1. 参与者触发事件。\n2. 系统校验条件并完成记录。",
    "branches": ["用户主动触发", "系统自动触发"],
    "exceptions": ["车辆状态异常"]
  },
  "postconditions": "事件记录可被查询。",
  "extensions": "<待确认>",
  "hmi": "显示处理结果。",
  "regulations": "<待确认>",
  "performance": "<待标定>",
  "nonfunctional": "数据一致性和可追溯性。"
}
```

字段缺少事实时使用 `<待确认>` 或 `<待标定>`；没有适用的分支/异常时返回 `[]`，不要返回空槽位。

## 3. 浏览器到业务后端

### 3.1 一键生成 UC

前端请求同源业务后端，不提交 PRD 正文：

```http
POST /api/v1/agent/generations
Cookie: ts_session=<浏览器登录后自动携带的HttpOnly Cookie>
X-Project-Request: 1
Idempotency-Key: <client_request_id>
Content-Type: application/json
```

```json
{
  "scene": "FROM_PRD_CREATE_UC",
  "project_id": "项目UUID",
  "function_id": "功能UUID",
  "source": {
    "kind": "PRD",
    "artifact_id": "PRD对象UUID",
    "revision_id": "已确认PRD版本UUID"
  },
  "client_request_id": "请求UUID"
}
```

后端会重新校验项目、功能、PRD 对象和当前已确认版本，并从只读业务数据库读取完整 `prd_markdown`。浏览器不能通过新增字段把伪造正文传给 Agent。

### 3.2 后端发给 Agent 的 UC 生成请求

```json
{
  "message": "按UC模板生成供审阅的候选，只返回约定JSON……",
  "scene": "FROM_PRD_CREATE_UC",
  "reference_data": {
    "source": {
      "kind": "PRD",
      "project_id": "项目UUID",
      "function_id": "功能UUID",
      "artifact_id": "PRD对象UUID",
      "revision_id": "已确认PRD版本UUID"
    },
    "prd_markdown": "完整PRD Markdown正文",
    "uc_template": {
      "template_id": "uc-default",
      "template_version": "1",
      "path": "/v1/agent/uc-template?scene=FROM_PRD_CREATE_UC",
      "auth_header": "X-Agent-Internal-Key"
    }
  },
  "response_format": "json",
  "idempotency_key": "请求UUID",
  "trace_id": "后端请求追踪ID",
  "timeout_seconds": 300
}
```

`prd_markdown` 是后端从已确认版本读取的完整正文；它不由浏览器提交，也不写入日志。`response_format` 是当前 TS 后端桥接请求字段，不是要求 Agent 工程新增技能 `output.schema`。

### 3.3 Agent 返回给业务后端的 UC 结果

后端只接受结构化 JSON，例如：

```json
{
  "scene": "FROM_PRD_CREATE_UC",
  "structured": {
    "use_cases": [
      {
        "name": "记录事件",
        "description": "系统记录事件。",
        "actors": "驾驶员；系统",
        "preconditions": "设备已上电。",
        "scenario": {
          "main_flow": "1. 触发。\n2. 记录。",
          "branches": ["主动触发"],
          "exceptions": []
        },
        "postconditions": "事件可查询。",
        "extensions": "<待确认>",
        "hmi": "显示结果。",
        "regulations": "<待确认>",
        "performance": "<待标定>",
        "nonfunctional": "可追溯。"
      }
    ]
  },
  "trace_id": "Agent追踪ID"
}
```

Markdown、代码围栏、空数组 `use_cases`、未知字段、缺失字段、固定结构之外的返回会被后端拒绝，不会被当成成功 UC。

## 4. Agent 查询 UC 模板

```http
GET /v1/agent/uc-template?scene=FROM_PRD_CREATE_UC
X-Agent-Internal-Key: <服务间密钥>
```

- 这是 Agent → 业务后端的服务间接口，不使用浏览器登录 Cookie 代替服务凭证。
- 后端返回 `template_id`、`template_version`、12 个顶层 `fields`、候选 `candidate_schema` 和实现说明 `instructions`。
- `number` 字段标记为 `generated_by: "backend"`；`scenario` 字段包含 `main_flow`、`branches`、`exceptions` 三个子字段。
- 认证失败不会泄露配置值；响应带 `X-Request-ID`，不返回密钥。

模板接口地址和 `AGENT_CALLBACK_KEY` 只放在业务后端/Agent 服务端配置中，不放入 `NEXT_PUBLIC_*` 或前端源码。

## 5. UC 图接口

### 5.1 浏览器请求

打开 UC 文件夹或后续“刷新”动作使用同源业务后端接口：

```http
POST /api/v1/agent/uc-diagram
Cookie: ts_session=<登录后的HttpOnly Cookie>
X-Project-Request: 1
Idempotency-Key: <client_request_id>
Content-Type: application/json
```

```json
{
  "scene": "FROM_UC_CREATE_UC_DIAGRAM",
  "project_id": "项目UUID",
  "function_id": "功能UUID",
  "known_uc_source_version": null,
  "client_request_id": "请求UUID"
}
```

`known_uc_source_version` 传上一次成功响应的 `source_version`；第一次请求传 `null`。

### 5.2 后端逻辑

1. 校验当前用户可访问项目和功能。
2. 只读取当前功能下所有已确认、未归档的 UC；临时草稿、未确认版本不进入图输入。
3. 没有已确认 UC：返回 `status: "empty"`，不调用 Agent。
4. 来源指纹未变化：返回 `status: "unchanged"`，不调用 Agent。
5. 指纹变化：把完整 UC 列表发送给 Agent。
6. 目前只返回 Mermaid 代码，不新增图表业务表。

### 5.3 Agent 请求和响应

后端发送的 `reference_data.uc_list` 中每一项包含 UC 身份和上述嵌套 12 字段结构；`number` 使用数据库已有正式编号。

```json
{
  "scene": "FROM_UC_CREATE_UC_DIAGRAM",
  "reference_data": {
    "source": {"project_id": "项目UUID", "function_id": "功能UUID"},
    "uc_source_version": "SHA-256指纹",
    "uc_list": [
      {
        "uc_id": "UC对象UUID",
        "uc_revision_id": "UC确认版本UUID",
        "prd_revision_id": "来源PRD版本UUID",
        "content": {
          "name": "记录事件",
          "description": "系统记录事件。",
          "number": "UC-01",
          "actors": "驾驶员；系统",
          "preconditions": "设备已上电。",
          "scenario": {"main_flow": "1. 触发。", "branches": ["主动触发"], "exceptions": []},
          "postconditions": "事件可查询。",
          "extensions": "<待确认>",
          "hmi": "显示结果。",
          "regulations": "<待确认>",
          "performance": "<待标定>",
          "nonfunctional": "可追溯。"
        }
      }
    ]
  },
  "response_format": "json"
}
```

期望 Agent 返回：

```json
{
  "scene": "FROM_UC_CREATE_UC_DIAGRAM",
  "structured": {
    "diagram_format": "mermaid",
    "diagram_code": "flowchart LR\n  A[\"驾驶员\"] --> B((\"记录事件\"))"
  },
  "trace_id": "Agent追踪ID"
}
```

本轮已实现请求、响应封套校验和指纹短路；前端数据库模式已实现打开/刷新触发、取消、缓存、迟到响应保护及 Mermaid 安全文本预览。Mermaid 依赖、图形渲染和真实 Agent 图形验收留到场景输出稳定后再做。
