# 54 PRD对话快捷入口纠偏与遗漏核查

> 日期：2026-10-08（Asia/Shanghai）。
> **状态：本地动线修复与本轮自动验证完成；用户手工验收待回执，未发布公司环境。**
> 用户要求：通过原有AI对话的快捷入口完成功能与PRD创建；不接受独立PRD创建弹窗，同时检查此前遗漏。
> 本文修正52号S3的错误交互，不取消52号后端创建意图、查重与任务记录规则。53号是FR/分配Skill说明，与本文不同。

## 1. 问题及根因

1. 快捷按钮只保留在 `MockProjectConversation`，真实数据库页面的 `LiveProjectConversation` 没有同等入口。因此本地真实数据模式比旧演示界面少了操作，不是“测试环境理应精简”。
2. 新PRD流程错误地接到独立 `PrdCreationDialog`。后端两阶段逻辑虽存在，用户实际入口和交互位置却不符合要求；接口/数据库测试通过不能替代动线验收。
3. 侧栏的 `＋ PRD生成` 被 `!props.readOnly` 条件隐藏；这里的 `readOnly` 同时被用于数据库模式，误伤了已实现的真实创建入口。
4. 真对话分支遗漏欢迎/建议内容和部分状态提示，且仍有“数据库项目暂不开放发送”的过期提示。
5. 内嵌化时必须额外保护：创建任务按项目和会话隔离、切会话后台结果不抢标签、持久任务卡不重复，以及任务记录迟到时不清空已经改好的功能名称。本轮均有针对性修正与回归。

## 2. 修正后的交互（本轮验收基准）

### 2.1 从原对话输入框开始

- 工作台中央对话和对象打开后的右侧对话都显示 `PRD生成`、`用例生成` 快捷入口。
- 选择 `PRD生成` 只选中快捷任务并聚焦原输入框，不请求Agent，不弹窗，不切换中间对象标签。
- 工作台 `生成PRD`、标签栏新建PRD入口、产品工程工作空间 `＋ PRD生成` 全部指向同一交互，不另开第二套表单。
- 在原输入框输入需求后点击发送或 Ctrl/⌘+Enter，一次提交沿现有创建意图执行：Agent计划名称 → 项目内查重 → 创建/明确复用功能 → 生成并保存待确认PRD。
- 无候选自动继续；发现同名/相似候选时，在本会话历史区的任务卡内选择复用、改名新建、打开已有PRD或退出。禁止按名称自动合并、覆盖功能元数据或重复建已有PRD。
- 成功才刷新目录、定位并打开唯一PRD标签；不自动确认PRD。

### 2.2 不破坏现有对话和任务

- 复用 `PrdCreationSession` 与现有API，不增加另一套业务流程、SQL或任务引擎。
- 创建意图的前端交互按 `project + thread` 隔离；当前任务嵌入匹配 `client_request_id` 的持久卡片。未拿到任务卡记录时先显示内嵌状态，不重复生成。
- 功能改名草稿保留在当前创建意图中：任务卡迟到、组件重挂载或切回原会话不会清空；开始另一项需求才重置。
- 系统任务不伪造普通聊天turn，不抢已有首问标题。已提交需求显示在任务内；有效提交清空本次输入，校验失败保留原输入。
- 切换项目/会话后原任务仍归原会话，不把旧任务控件显示在新会话，也不让后台完成强行切换当前中间标签。
- 停止只停止前端等待，不谎称已取消后端。响应丢失先只读查询回执；生成失败若已绑定功能，只继续原意图/原功能。
- 保留“我的会话”置顶、历史区独立滚动、底部输入区，不增加问答/修改操作下拉。
- 普通聊天未主动添加对象时仍发送空附件列表，不偷偷引用当前标签。进入快捷模式沿用既有互斥规则：移除已选对象附件并提示；明确添加对象则退出快捷模式。
- 刷新后持久任务与已保存对象可读；**未结束的内存候选交互不承诺跨浏览器刷新恢复**。不把历史记录可读等同于所有临时控件持久化。

### 2.3 用例快捷入口的真实能力边界

真实入口选择当前项目已有且PRD已确认的功能，明确点击 `生成UC` 复用现有PRD→UC批量追加接口。保留全部旧UC，新批次为待确认；仅定位并展开左侧需求工程UC文件夹，中间工作区不切换。输入框里另写的聊天草稿不发送给这个批量任务，界面有明确提示。

这不是旧Mock中“凭聊天提示补充单条UC”的实现：该业务契约没有在当前真实接口中补齐，不能通过注入测试A/B/C或假结果假装支持。若后续仍需要这个独立场景，须另行对齐，不在本轮猜协议。
