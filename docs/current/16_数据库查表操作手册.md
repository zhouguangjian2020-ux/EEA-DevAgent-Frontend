> 更新：2026-09-22（Asia/Shanghai）。适用于公司服务器192.168.64.3上的ee_platform；依据已部署R2脚本和用户回传，不是重新建库手册。

## 1. 每张表叫什么、做什么

当前实际建表为 **ee下29张业务表 + ee_admin下1张迁移记录表**，以下列全30张。不把尚未建表的3张M1 AI表或二期设计列进去。ee和ee_admin是同一数据库中的两个schema（表的命名空间），不是两个数据库。

| 序号 | 完整表名 | 中文用途 | 具体存什么 / 查什么 |
|---|---|---|---|
| 1 | `ee.projects` | 项目 | 项目编号、名称、归档信息；项目是业务数据隔离边界。 |
| 2 | `ee.business_functions` | 业务功能 | 项目内的功能，如行车记录仪DVR；每个功能拥有一个PRD对象。 |
| 3 | `ee.app_users` | 业务用户 | 认证系统主体与业务用户的映射，不存登录密码；不是PostgreSQL登录角色。 |
| 4 | `ee.project_members` | 项目成员 | 用户是否属于项目及成员状态；角色授权另看access_bindings。 |
| 5 | `ee.artifact_types` | 对象类型 | 注册PRD、UC、FR、FR_ALLOCATION四类对象及固定工作台。 |
| 6 | `ee.artifact_type_versions` | 类型metadata版本 | 字段、说明、展示/编辑描述、结构/接受校验规则的版本；解释历史对象的依据。 |
| 7 | `ee.artifacts` | 对象主表 | 稳定ID和业务编号；保存当前工作版、当前已接受版两个独立指针。 |
| 8 | `ee.artifact_revisions` | 公共版本头 | 版本号、基版、来源、作者及绑定metadata版本；正文另存各类型版本子表。 |
| 9 | `ee.prds` | PRD身份 | 关联PRD对象及所属功能；不是正文存放位置。 |
| 10 | `ee.prd_versions` | PRD正文版本 | markdown_body保存整份普通长文本/Markdown，不强制拆固定章节JSON。 |
| 11 | `ee.use_cases` | UC身份 | UC稳定身份及其所属PRD。 |
| 12 | `ee.uc_versions` | UC正文版本 | UC名称、描述、参与者、主事件流等及依据的PRD版本；分支/异常另存子表。 |
| 13 | `ee.uc_scenario_items` | UC场景子项 | 某UC版本的分支和异常条目；主事件流不在此表，不为显示空槽造记录。 |
| 14 | `ee.functional_requirements` | FR身份 | FR稳定身份；FR不直接绑定唯一来源UC。 |
| 15 | `ee.fr_versions` | FR正文版本 | 各FR版本的需求描述；编号来自artifacts.code。 |
| 16 | `ee.fr_uc_sources` | FR来源关系 | 某FR版本引用的一个或多个UC对象及具体UC版本。 |
| 17 | `ee.project_subsystem_designs` | 项目子系统方案入口 | 项目方案入口及当前方案版本指针。 |
| 18 | `ee.subsystem_design_versions` | 子系统方案版本头 | 整套子系统目录的版本号、来源和说明；条目在subsystem_version_items。 |
| 19 | `ee.subsystems` | 子系统稳定身份 | 项目内子系统ID和代码；名称/职责保存在方案版本条目中。 |
| 20 | `ee.subsystem_version_items` | 方案内子系统条目 | 某方案版本的名称、职责、域分组、顺序、可分配标记及原始来源。 |
| 21 | `ee.fr_allocations` | FR分配身份 | 某FR对应的分配工作对象，与FR正文分开审阅/留版本。 |
| 22 | `ee.allocation_versions` | 分配版本 | 固定本次分配所依据的FR版本和子系统方案版本。 |
| 23 | `ee.allocation_targets` | 分配目标 | 某分配版本选择的一个或多个子系统，按该次方案版本解释。 |
| 24 | `ee.permission_definitions` | 业务能力点 | 业务资源/动作及可授权范围；不是PostgreSQL数据库权限表。 |
| 25 | `ee.access_roles` | 业务角色 | 应用内角色定义；不是可用于psql登录的数据库角色。 |
| 26 | `ee.role_permissions` | 角色能力关系 | 业务角色包含哪些能力点。 |
| 27 | `ee.access_bindings` | 授权范围绑定 | 授予用户业务角色并限定项目/功能/对象范围。 |
| 28 | `ee.security_audit_events` | 安全审计 | 成员、授权等敏感操作审计；before/after不是正文版本。 |
| 29 | `ee.review_events` | 审阅事件 | 针对版本的接受/拒绝决定、操作者、顺序和原因；R2未开放撤回。 |
| 30 | `ee_admin.schema_migrations` | 建表迁移记录 | 迁移号、DDL文件SHA-256、执行时间及执行人；不存业务正文。 |

**最常用的找表路线：**

- 看PRD原文：`artifacts → head_revision_id → prd_versions.markdown_body`。
- 看UC正文：`artifacts → head_revision_id → uc_versions`；分支/异常再查`uc_scenario_items`。
- 看FR描述及来源：`fr_versions + fr_uc_sources`，来源固定到UC对象ID和版本ID。
- 看“某FR分给了哪个子系统”：`fr_allocations → allocation_versions → allocation_targets → subsystem_version_items`，使用分配当时固定的方案版本，不直接套最新名称。
- 看项目完整子系统目录：`project_subsystem_designs.current_version_id → subsystem_version_items`；本次是43项，不是只看有FR分配的几项。
- 看metadata：`artifact_type_versions`；看某对象实际使用哪份定义，要沿`artifact_revisions.type_version_id`找，不要一律取最大版本号。

## 3. 从哪里运行命令：按三步进入只读查询

### 3.1 Windows PowerShell：连接服务器

如果你已经在`t7920@t7920:~$`，跳过这一条。

```powershell
ssh.exe -p 22 t7920@192.168.64.3
```

22是SSH端口，5432是PostgreSQL端口，不要混用。不要求Windows直连5432，不修改防火墙/HBA/监听。

### 3.2 Ubuntu终端：启动只读psql会话

在`t7920@t7920:~$`下完整执行：

```bash
cd /
sudo -v
sudo -u postgres env PGCLIENTENCODING=UTF8 PGOPTIONS='-c default_transaction_read_only=on -c statement_timeout=15000 -c lock_timeout=3000' \
  /usr/lib/postgresql/18/bin/psql \
  -X -w -h /var/run/postgresql -p 5432 -U postgres -d ee_platform \
  -v ON_ERROR_STOP=1 -P pager=off
```

- sudo如提示密码，输入服务器`t7920`用户的sudo密码，不是数据库密码。
- 使用服务器本机Unix socket和现有管理员身份；无需创建数据库登录账号，不给`ee_m0_owner`设置密码。
- `-X`不加载个人psql启动配置；默认每个新事务只读；单条语句超时15秒、锁等待超时3秒。
- 这是管理员的误操作防护，**不是独立的最小权限只读账号，也不证明应用权限已接通**。不要关闭只读设置，不运行INSERT/UPDATE/DELETE/DDL、迁移/导入或其他写函数。
- 本手册查询采用自动提交的短查询，不需要一直挂着BEGIN事务。用户/审计信息只用于授权排查，分享输出前注意遮蔽身份等敏感内容。

### 3.3 psql内部：确认目标与只读状态

进入后一般看到`ee_platform=#`。以下块在psql内部粘贴，不是Ubuntu Bash或PowerShell：

```sql
\conninfo
\x auto
SELECT current_database() AS database, current_user AS db_user;
SHOW port;
SHOW data_directory;
SHOW default_transaction_read_only;
SHOW transaction_read_only;
SELECT system_identifier::text FROM pg_control_system();
```

核对：库`ee_platform`、端口5432、目录`/data/postgresql/18/main`、两个read_only均为`on`、集群标识`7686454253092706426`。不一致就退出并回传，不继续查错库。

**约定：**后面所有sql块在这个psql会话内运行。SQL以英文分号`;`结束；以`\`开头的是psql命令，单独一行、末尾不加分号。

## 5. 每张表都怎么查：逐表可复制命令

这些是**管理员跨项目的原始表预览**，每条最多20行，不是应用侧权限过滤。正文仅取预览，避免长文/metadata刷满终端。只复制需要的一条；0行也可能是正常状态。

看任一表全部列可照此格式：`SELECT * FROM ee.uc_versions LIMIT 20;`。查询具体业务对象及关联，优先用第6节，不凭某子表“第一行”判断对应哪份正文。


### 5.2 类型metadata和通用对象版本


### 5.3 PRD、UC、FR内容与来源

```sql
-- PRD身份：ee.prds
SELECT artifact_id, project_id, function_id, type_code

SELECT uc_revision_id, item_id, kind, category, position, left(body, 120) AS body_preview

-- FR身份：ee.functional_requirements
SELECT artifact_id, project_id, function_id, type_code

SELECT revision_id, fr_id, left(description, 160) AS description_preview

-- FR来源关系：ee.fr_uc_sources
SELECT fr_revision_id, uc_id, uc_revision_id, rationale
FROM ee.fr_uc_sources ORDER BY fr_revision_id, uc_id LIMIT 20;
```

## 6. 常用业务查询：按项目、对象、真实版本找内容

### 6.1 先设置查询范围

以下是psql变量，**只改变查询条件，不修改数据库**。后面的`:'project_code'`由psql引用为SQL字符串，不要直接搬到不支持psql变量的其他工具。

### 7.3 把字段和嵌套场景展开，便于阅读

```sql
WITH bound AS (
  SELECT tv.field_catalog
  FROM ee.artifacts a
  JOIN ee.projects p ON p.id = a.project_id
  JOIN ee.business_functions bf ON bf.id = a.function_id AND bf.project_id = a.project_id
  JOIN ee.artifact_revisions r ON r.id = a.head_revision_id
  JOIN ee.artifact_type_versions tv ON tv.id = r.type_version_id
  WHERE p.code = :'project_code' AND bf.code = :'function_code'
    AND a.code = :'object_code'
), top_fields AS (
  SELECT field, ord
  FROM bound CROSS JOIN LATERAL jsonb_array_elements(field_catalog) WITH ORDINALITY x(field, ord)
), expanded AS (
  SELECT ord AS parent_order, 0::bigint AS child_order, field FROM top_fields
  UNION ALL
  SELECT t.ord, c.ord, c.field
  FROM top_fields t
  CROSS JOIN LATERAL jsonb_array_elements(coalesce(t.field->'children', '[]'::jsonb)) WITH ORDINALITY c(field, ord)
)
SELECT parent_order, child_order, field->>'key' AS field_key,
       field->>'path' AS content_path, field->>'label' AS label,
       field->>'description' AS description, field->>'widget' AS widget,
       field->>'edit' AS edit_rule, field->'visible_in' AS visible_in,
       field->'validation' AS validation
FROM expanded ORDER BY parent_order, child_order;
```

展开R2目录顶层及一层children。UC仍保留12个正文展示项；catalog还包含PRD来源等关系描述，**不要把catalog条目数当成UI顶层字段数**。编辑类别也不是当前用户“可以编辑”的最终权限结论；仍需后端结合身份、状态和权限计算。

## 8. 查询出错或看不清怎么办

| 现象 | 处理 |
|---|---|
| 提示符是t7920@t7920:~$，输入SELECT报找不到命令 | 还在Ubuntu终端，先执行3.2进入psql。 |
| 提示符变为ee_platform-# | SQL未结束，检查分号。放弃可按Ctrl+C或输入`\r`清空缓冲，不要乱补写入语句。 |
| 底部出现(END)翻页器 | 按q回到psql，然后`\pset pager off`。本手册连接已默认关闭翻页器。 |
| 长正文挤在一起 | `\x on`改为逐字段显示；用完`\x auto`恢复自动布局。 |
| relation ... does not exist | 先按3.3核对库/集群，再按4.1确认schema；检查ee.前缀和表名，不重新建表。 |
| permission denied / Peer authentication failed / sudo失败 | 回传报错核对连接身份；不要chmod/chown数据目录、修改HBA、授予PUBLIC权限。 |
| syntax error at or near ':' | 可能在非psql工具中运行，或没按6.1设置变量；不要删引号硬拼字符串。 |
| 查询0行 | 查项目/功能/对象编号及大小写，区分无工作版、无接受版、无审阅事件；不要自动补数据。 |
| 语句或锁超时 | 保留报错、停止该查询，不重启服务、不杀其他会话、不全局关闭超时。 |
| 提示事务已失败 | 若自行开启过事务，`ROLLBACK;`结束该只读事务后再排查；本手册无需手动BEGIN。 |

退出psql返回Ubuntu终端：

```sql
\q
```

再退出SSH时在Ubuntu终端输入exit；这不会停止PostgreSQL。不要把DROP/DELETE/TRUNCATE、migrate、seed或smoke当成查表命令；smoke有临时写入再回滚，不属于本手册只读查询。
