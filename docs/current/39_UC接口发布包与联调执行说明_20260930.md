# 39 UC接口发布包与联调执行说明（2026-09-30）

## 1. 当前完成状态

本轮已完成 UC 生成、UC 模板查询、UC 图桥接接口的本地实现、契约测试和配套发布包准备。公司服务器尚未操作；没有 SSH、公司数据库连接、数据库迁移、容器重启或 Agent 工程修改。

已确认的产品边界仍然有效：

- UC 生成结果只作为候选展示，不自动创建正式 UC、不自动确认。
- 正式 UC 有 12 个顶层字段；`scenario` 内含 `main_flow`、`branches[]`、`exceptions[]`。
- 分支/异常数量由 PRD 决定，不强制 4/5，也不填充空槽位。
- `number` 由业务后端正式保存时生成，Agent 候选不返回正式编号。
- UC 图接口暂定返回 Mermaid；数据库模式前端已接入 UC 文件夹打开/刷新触发、状态处理和安全文本预览，Mermaid 图形渲染仍等待 Agent 输出契约稳定后再接入。
- UC 图使用 `known_uc_source_version` 指纹短路；未变化时不调用 Agent，第一版不增加图持久化表。

## 2. 接口和出站契约

### 2.1 浏览器 → 业务后端

浏览器通过同源 `/api` 访问业务后端，使用登录后的 HttpOnly `ts_session` Cookie。浏览器不提交 PRD 正文，也不携带 Agent Key。

```http
POST /api/v1/agent/generations
Cookie: ts_session=<登录后自动携带>
X-Project-Request: 1
Idempotency-Key: <client_request_id>
Content-Type: application/json
```

```json
{
  "scene": "FROM_PRD_CREATE_UC",
  "project_id": "项目UUID",
  "function_id": "功能UUID",
  "source": {
    "kind": "PRD",
    "artifact_id": "PRD对象UUID",
    "revision_id": "已确认PRD版本UUID"
  },
  "client_request_id": "请求UUID"
}
```

业务后端会重新检查项目、功能、PRD 类型和当前已确认版本，并从只读业务数据库读取完整 `prd_markdown`。

UC 图请求：

```json
{
  "scene": "FROM_UC_CREATE_UC_DIAGRAM",
  "project_id": "项目UUID",
  "function_id": "功能UUID",
  "known_uc_source_version": null,
  "client_request_id": "请求UUID"
}
```

首次请求传 `null`；下一次把上次响应的 `source_version` 原样传回。返回 `empty` 或 `unchanged` 都是不需要调用 Agent 的正常结果。

### 2.2 业务后端 → Agent（UC 生成）

```json
{
  "message": "按UC模板生成供审阅的候选，只返回约定JSON……",
  "scene": "FROM_PRD_CREATE_UC",
  "reference_data": {
    "source": {
      "kind": "PRD",
      "project_id": "项目UUID",
      "function_id": "功能UUID",
      "artifact_id": "PRD对象UUID",
      "revision_id": "已确认PRD版本UUID"
    },
    "prd_markdown": "业务后端从已确认PRD版本读取的完整正文",
    "uc_template": {
      "template_id": "uc-default",
      "template_version": "1",
      "path": "/v1/agent/uc-template?scene=FROM_PRD_CREATE_UC",
      "auth_header": "X-Agent-Internal-Key"
    }
  },
  "response_format": "json",
  "idempotency_key": "请求UUID",
  "trace_id": "业务后端请求追踪ID",
  "timeout_seconds": 300
}
```

Agent 必须返回 `structured.use_cases` 数组。每个候选包含 11 个内容字段，不包含 `number`、`candidate_id`、`ordinal`、正式对象 ID 或版本 ID。业务后端仅为响应展示临时生成 `candidate_id`/`ordinal`，不落库。

### 2.3 Agent → 业务后端模板查询

```http
GET /v1/agent/uc-template?scene=FROM_PRD_CREATE_UC
X-Agent-Internal-Key: <AGENT_CALLBACK_KEY>
```

模板接口只接受服务间凭证，浏览器登录 Cookie 不能替代该凭证。Agent 工程师需要把业务后端地址和该服务间密钥配置在 Agent 服务端；本项目不修改 Agent 工程。

## 3. 登录态模拟

脚本：

```text

```

脚本使用同一个 `httpx.Client`，顺序执行登录、`/v1/auth/me`、UC 生成和 UC 图请求，因此登录返回的 HttpOnly Cookie 会自动复用；也支持关闭其中一个请求、用隐藏输入提示密码并发送浏览器样式 `Origin`。脚本不打印密码、Cookie、Agent Key、回调密钥或完整 DSN。

```powershell
$env:UC_API_BASE_URL = "http://127.0.0.1:8000"
$env:UC_USERNAME = "engineer01"
$env:UC_PASSWORD = "<从安全输入或临时环境变量提供>"
$env:UC_PROJECT_ID = "<项目UUID>"
$env:UC_FUNCTION_ID = "<功能UUID>"
$env:UC_PRD_ID = "<PRD对象UUID>"
$env:UC_PRD_REVISION_ID = "<已确认PRD版本UUID>"
# 首次请求可不设置；重试/刷新时设置上一次 source_version
$env:UC_KNOWN_UC_SOURCE_VERSION = "<64位小写SHA-256，可选>"
& E:\Git projects\TS-backend\.venv\Scripts\python.exe E:\Git projects\TS-backend\tools\simulate_uc_requests.py
```

这个脚本验证的是“浏览器登录态 → 业务后端”。业务后端向 Agent 的完整正文、模板引用、UC 嵌套结构和 Mermaid 响应用受控 HTTP mock 测试验证，不在脚本中直接暴露 Agent 密钥。

## 6. 公司部署边界与下一步

本轮没有执行公司服务器操作。用户在公司服务器上执行发布包内 `DEPLOYMENT.md` 的命令前，应先只读检查：

1. 当前 `ts-agent-backend` 容器、7000端口和 `/data/ts-platform-managed/20260929` 旧发布目录；
2. 7100端口、Nginx现有配置和前端发布目录是否已占用；
3. 服务器 Node/Docker 版本是否满足发布包要求；
4. 当前 `.env` 是否已有正确的 `PROJECTS_DATABASE_URL`、`PROJECTS_WRITE_DATABASE_URL`、`AGENT_INVOKE_URL`、`AGENT_API_KEY`、`AGENT_CALLBACK_KEY`、CORS 和超时配置。

确认后再以新版本目录构建/启动，不能在同一端口并行启动两个服务，也不要先删除旧容器。数据库不需要因为这两个桥接接口新增迁移；正式 UC 保存若未来要支持历史固定约束之外的任意分支/异常数量，仍需单独核对数据库约束。

上线验收必须区分：

- 本地质量门禁通过；
- 公司后端新镜像/进程已启动；
- 公司 Agent 真实确认 `FROM_PRD_CREATE_UC`、模板回调和 `FROM_UC_CREATE_UC_DIAGRAM` 的输入输出；
- 公司浏览器登录态和 `/api` 反向代理真实可用。

当前可以交给 Agent 工程师的最小确认清单：

- 是否读取 `/v1/agent/uc-template?scene=FROM_PRD_CREATE_UC`，并带 `X-Agent-Internal-Key`；
- 是否读取 `reference_data.prd_markdown` 并返回 `structured.use_cases`；
- 是否不返回 `number` 等后端字段；
- UC 图是否返回 `structured.diagram_format="mermaid"` 和非空 `diagram_code`；
- 是否保留 `scene` 和 `trace_id` 字段。
