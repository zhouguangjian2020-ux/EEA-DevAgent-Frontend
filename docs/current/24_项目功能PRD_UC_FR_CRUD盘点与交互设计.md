**多选删除模式与附件选择分离**

- 功能、PRD、UC、FR、FR分配的真实对象行显示删除选择框；底部固定“已选N项 / 取消 / 删除所选”，按业务身份去重计数。分类文件夹和子系统分组不作为删除对象。
- 现有普通复选框用于AI附件。进入多选删除时明确标记模式，使用独立的待删除选择集合，不把附件勾选当删除授权；退出后原附件选择不受影响。
- 勾选功能不自动勾选或删除其内容，勾选分类不能隐式创建一个批量级联操作；只删除用户明确选中的真实对象。
- 同一个分配对象在多个子系统位置出现时，选择状态同步且只算一项。真实零目标分配也有选择入口；无分配对象的FR不制造假条目。
- 批次限定同一项目，沿用项目隔离；功能资料编辑仍在各自标签页中，不因批量删除而增加批量重命名/统一改描述。

**批量依赖与事务规则**

- 先对整个选择集合检查：存在未选中、未删除的下游引用则阻止整批，并列出被阻止目标和有权查看的依赖，不提供强制删除。
- 批次内部选中对象之间的依赖可按顺序处理。例如选中FR及其分配，可先删分配再删FR；只选PRD仍有关联UC则失败；PRD及全部UC都选中但UC仍被批次外FR引用，同样失败。
- 统一弹窗展示总数、各类型数量及目标清单，一次确认。存在未保存输入时在同一框提示丢弃，取消不影响原草稿；分配列出全部目标子系统。
- 后端一次事务重查权限、版本与依赖，按FR分配→FR→UC→PRD→功能的合法顺序处理；任一失败则整批不删。不允许前端循环多次DELETE、已经删掉一部分后再显示整批失败。
- 不自动补选、清理或级联任何未选中对象；前端成功后再一次性同步树、标签和空子系统节点。冲突/失败保留选择并说明原因，重试使用原操作标识防重复。
- 功能还有未选中的有效内容时阻止删除；若所有内容都明确选中且无批次外依赖，可在同一事务最后删除功能。单选功能时等价于只允许删除空功能。

**FR分配树：必须能定位真实分配对象**

当前树只展示子系统节点，不能在FR分配分类或子系统行上放一个会误删一批对象的“删除分配”。拟在已有FR分配分类内组织如下，只是同一分配对象的视图分组，不新建业务对象或详情页：

    FR分配
    ├─ 视频处理子系统
    │  ├─ FR-001 · 分配                         [⋯]
    │  └─ FR-002 · 分配                         [⋯]
    ├─ 存储子系统
    │  └─ FR-001 · 分配                         [⋯]
    └─ 未选择子系统
       └─ FR-003 · 分配                         [⋯]

- 同一FR分配到多个子系统时，可以出现多个导航位置，但它们引用同一个allocation_id。行名加“· 分配”，区别FR分类中的FR正文对象。
- 分配行名称打开既有当前功能FR分配全景并定位该FR行，不新开单个分配详情/编辑页；子系统分组仅展开/折叠，不补造子系统详情能力。
- “删除该FR的全部分配”删除这一分配对象及它对所有子系统的活动关联，不是只解除当前子系统的一条关系。确认框列出涉及的全部子系统，明确“保留FR和子系统目录”；不额外加入“仅移出当前子系统”写操作。
- “未选择子系统”是虚拟分组，仅当存在真实的零目标分配对象时出现，使空分配也能被删除；**无分配对象的FR不制造假分配行**。分组无内容即隐藏，不能因为空子系统隐藏规则让空分配无法访问。
- 删除成功后，同一allocation_id在所有子系统下的导航位置一起消失；仍有其他FR的子系统保留，无FR的子系统隐藏。“FR分配”固定分类保留。
- 当前database.ts只把分配转成FR→子系统数组；实施需保留后台返回的allocation_id、FR身份、版本/状态，导航位置ID与业务目标ID分开，不能用FR ID、子系统ID或名称代替分配ID发DELETE。分配行只提供定位和菜单，不新增原先没有的附件勾选能力；重复导航位置也不能被当成多个业务对象。

**一个确认弹窗处理允许/阻止两种结果**

1. 点击菜单后固定项目/功能/类型/ID，打开确认框并读取删除检查；检查期间危险按钮不可用。弹窗标题含类型、编号/名称，不按显示名称定位对象。
2. 有引用：显示“暂不能删除”及引用数量/可访问对象列表，只提供查看引用/关闭，不提供强制删除。搜索过滤或当前展开内容不能代替后端全范围依赖查询。
3. 无引用：说明删除后不提供恢复；分配额外列出全部目标并说明不会删除FR/子系统，PRD说明之后可新建。用一次取消/删除确认，不再套多轮确认或要求输入名称。
4. 对象存在未保存输入时在同一确认框追加“未保存修改将丢弃”；用户确认删除后不先保存新修订，也不再重复弹普通关闭标签提示。取消/失败则完整保留草稿。
5. 提交中锁定危险按钮；后端事务内重查，引用/版本变化转为冲突提示。成功后再更新树和受影响标签，失败不移除对象。
6. 普通对象删除后关闭其详情标签；分配删除只刷新仍打开的FR分配全景，不关闭整个全景，也不关闭或删除FR正文。PRD删除后刷新功能全景的创建资格，不自动新建。
7. 同功能在所有一级工作空间保持一致；不删除其他功能/项目草稿或项目对话。菜单Escape/外部点击关闭并还原焦点，切项目/工作空间关闭旧浮层，迟到结果只归原目标。

**功能删除规则已确认，项目删除仍单独定稿**

单选非空功能禁止删除；批量选择时仍有未选中的有效内容就阻止整批，全部内容明确选中且可合法删除后才在事务末尾删除功能。不做父级整体隐藏或隐式级联，检查整个功能而非当前模块/搜索结果。共享功能在所有模块同步移除。本次确认不替用户决定项目删除规则。

## 4. 删除规则（后端单删已实现待验收，UI/多选未实施）

### 4.1 删除是业务终态；底层只保留历史

用户已同意“依赖阻止删除、PRD删后可重新创建、底层保留历史但本轮不做恢复界面”。界面执行删除，底层使用既有archived_at等标记退出活动使用，不物理清除历史正文、引用或审计。

- **不恢复原对象，不做回收站、已删除列表、restore接口或永久清空。**保留历史不意味着向用户提供可恢复对象。
- 不将删除伪装成取消编辑或关闭标签；不把再次创建实现成隐式恢复旧ID。
- 删除对象不得继续读取为活动对象、编辑、确认或被新内容选作来源；后台历史不得因为刷新、迟到响应或生成结果重新进入活动集合。

### 4.2 按依赖阻止删除，不自动级联

| 删除对象 | 已确认的阻止条件 | 无阻止条件时 |
|---|---|---|
| PRD | 仍有关联的未删除UC | 允许删除；该功能可新建PRD |
| UC | 仍被未删除FR引用 | 允许删除 |
| FR | 仍有未删除FR分配对象，**包括未选择子系统的空分配** | 允许删除 |
| FR分配 | 当前不另设下游业务依赖门槛，不要求先取消确认 | 草稿/已确认分配均可删除 |

- 检查真实对象关系；未确认草稿中的关联也计入。已删除的下游不继续阻挡上游删除。
- 删除FR分配只移除分配对象的活动可见性，不删除FR或项目子系统目录记录，也不改写它们的历史。
- 需要清理整条依赖链时，由用户依次删除分配→FR→UC→PRD；不提供隐式级联清除。
- “可随时删除分配”指没有上述下游依赖门槛，不等于跳过既有登录、项目读写授权、请求防护、并发或事务检查。
- **本轮新增FR分配删除，但不因此开发其完整创建/编辑/确认链路。**

### 4.3 子系统工作空间节点按实际FR关联显示

用户确认：当某个子系统在当前工作空间范围内没有任何FR时，列表中不应继续存在它的文件夹/节点。

- 按当前项目、当前功能的未删除FR与未删除分配关系计算，不以项目完整子系统目录直接铺满树。
- 删除/移除最后一条关联后隐藏该子系统节点；仍有其他FR关联则保留；后续重新产生有效关联时重新显示。
- 只改变派生的导航节点，不删除子系统目录数据，不影响其他功能的同名子系统，不新增子系统详情/编辑能力。
- 需求工程下固定的UC、FR、FR分配分类文件夹继续保留；“空子系统节点隐藏”不等于删除这些固定空分类。
- 本条约束工作空间列表，不改变P-002“子系统需求图只采用已确认分配”的独立规则。
- 2026-09-28只读复核发现：projectWorkspaceTree在存在任一分配时仍遍历完整subsystems目录，并把未使用项标为“当前未使用”；本轮尚未改代码，后续需改为按有效FR关联过滤，并测试最后一条关联消失和多FR共用子系统的情况。

### 4.4 PRD唯一性改为“未删除PRD唯一”

产品规则已经确认：**一个功能最多有一份未删除PRD；没有关联UC时可以删除；删除后重新创建新对象，不恢复原对象。**

冻结R2及未应用阶段2增量的数据库仍是以下旧基线：

1. artifacts_one_prd_per_function索引未排除已归档PRD。
2. prds表还有UNIQUE(project_id, function_id)。
3. 阶段2以前的create_artifact会因任一旧prds身份拒绝重建；阶段2已改为只检查活动PRD，并验证workspace资格与旧ID不得复用。

阶段2已用独立deletion-20260928包同时调整两层唯一性和创建检查，保留历史表不可变保护及UC到具体旧PRD的引用；不能只修改一个索引。并发创建仍只能成功一份活动PRD，新PRD使用新ID/新草稿，不继承旧对象的确认状态；新UC只能选择当前有效PRD。冻结R2和旧发布包不改。

FR分配也有按FR的身份唯一约束。其删后再次创建/生成的接口尚未实施，应在后续分配写入设计中明确，不能用重新启用旧分配冒充新建；本轮不借删除扩展成完整分配CRUD。

### 4.5 剩余两项边界已确认（2026-09-28）

用户已分别批注“同意”26号Q-01/Q-02，不再列为待确认。以下规则已在阶段2单对象后端实现并验证，前端及多选仍待阶段3/4。

- **非空项目禁止删除**：有任何未删除功能或其他活动业务内容时阻止；先按已确认流程清理功能，再单独删除空项目，不自动级联。成员、初始化子系统目录、已删除业务历史和审计无需物理清空。删除当前项目后回项目选择，不擅自切换其他项目。

### 4.6 提交、同步和失败

- 删除前展示目标与阻止原因；后端在短事务内重新检查权限、版本、祖先状态及引用，不能直接信任旧预检查结果。
- 删除与创建、保存、确认使用一致的锁定/有效性检查次序，避免检查后新增引用；前端按钮置灰不能代替后端判断。
- 未保存输入先提醒，不静默丢弃；数据库成功后再关闭受影响对象标签、刷新树和全景。无关对象草稿及项目对话保持不变。
- 版本/引用变化返回冲突；失败不移除对象。超时重试沿用操作标识，迟到响应不复活删除对象。
- 编号和身份稳定，删除不触发其他对象重编号；重新创建不是复用已删除ID。
