## 2. 合并单元格如何处理

- 两份Excel各6个工作表。每份仅封面有7个合并区域；实际行车记录仪FR/分配表没有合并单元格。未把空白D列向下填充，未把封面标题误当数据。
- UC Word表采用4列物理网格，包含77个带横跨列的单元格、41个纵向合并标记。按OOXML `gridSpan` / `vMerge`恢复逻辑层级，只传播显式合并格，不对普通空白猜测填充。
- 场景大类跨主流程/分支/异常；异常大类又跨5行。依类别标签恢复，不按固定行号硬读，因此19行/20行的UC表都能正确提取。
- PRD正文44个表未发现横向/纵向合并标记，按原正文顺序生成Markdown表。Word原排版、自动编号、页眉页脚不冒充已无损转换；需确认转换稿后入库。
- 两份docx均未发现正文tracked insertion/deletion或嵌套表格；各一个图片资源仅由页眉引用，没有把页眉图标当UC的HMI正文。UC-001的HMI格是空白文本，不从其他地方补图或造内容。

本轮是结构/数据提取核查，不是Word逐页版式验收。原文件未修改，全部来源SHA-256写入audit.json便于重现。
