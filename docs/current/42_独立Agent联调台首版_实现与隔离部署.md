## 实现范围

- UC生成、UC模板、UC图三条真实业务后端接口；另有既有PRD生成/扩写流式验证入口。
- 原业务登录态由联调服务持有；浏览器独立HttpOnly会话，Agent/回调/诊断Key不进入浏览器。
- JSON预置参数可编辑，服务器生成请求UUID；当前公司目标为“新项目 / DVR”，具体身份见43号，以部署白名单与实际请求为准；不得默切旧测试项目。离线儿童锁仍是合成演示。
- 应用层方向独立展示、后台读库SQL/参数/实际读取结果、Agent发送/返回、可关联模板回调、脱敏短期历史与导出。
- 流式实时正文、事件、最终结果；200不是成功，error/中断保留部分正文，停止等待不证明Agent已取消。
- 原业务后端增加可关闭采集，默认关闭；Key+签名Cookie+项目白名单；有界内存记录与独立服务增量拉取，没有消息队列或数据库迁移。
- 原产品前端代码、Agent源码、业务表与冻结包未改；不提供保存/确认/删除接口按钮。

## 部署注意

新发布包的两个镜像均选Python3.12；旧后端源码Dockerfile和历史包保持不变。原因是既有PRD流式代码使用 `asyncio.timeout`，旧3.10不满足该调用。没有在这一步重构业务超时逻辑。

新后端.env复制旧配置但只写新文件；预览中业务写入关闭。原Key不打印；独立诊断Key随机生成且与联调服务一致。模板回调Key仍是AGENT_CALLBACK_KEY，不是AGENT_API_KEY。

原始模板回调如果没有 `X-Request-ID=<invoke.trace_id>`，无法精确归入同一次测试，页面不能补造。压缩上游、限额满、超时及采集缺失均标记不完整。
