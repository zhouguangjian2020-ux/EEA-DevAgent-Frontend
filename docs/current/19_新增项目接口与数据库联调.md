- 日期：2026-09-22
- 范围：项目切换窗口新增空项目；后端 `POST /v1/projects`；公司数据库最小创建权限授权。
- 当前实施状态：代码已实现并在隔离 PostgreSQL 18 + 真实 HTTP + 浏览器中验证；公司数据库专用创建账号尚未由用户执行授权，不能把本地验证写成公司库已完成。

## 1. 功能结果

切换项目窗口增加：

```text
＋ 新增项目
```

新增表单只有：

| 字段 | 规则 |
|---|---|
| 项目名称 | 必填，去首尾空格后1～100字符；允许重名 |
| 项目说明 | 选填，去首尾空格后最多2000字符 |

项目编号格式为 `PRJ-` 加创建请求UUID的大写十六进制，系统生成且稳定。创建人来自当前Cookie登录主体，不接受浏览器指定。

创建事务会写入现有表：

1. `ee.projects`：项目基本信息；
2. `ee.project_members`：创建人加入项目；
3. `ee.access_bindings`：创建人的项目级读取绑定；
4. `ee.project_subsystem_designs`：空的子系统方案入口，`current_version_id`为空；
5. `ee.security_audit_events`：创建审计。

不会写入`business_functions`、`artifacts`、`subsystems`、PRD、UC、FR或分配数据。创建后工作空间的`functions`为空，并显示空项目提示。

## 2. 接口契约

### 2.1 `POST /v1/projects`

请求：

```json
{
  "creation_id": "客户端为本次表单生成的UUID，超时重试时保持不变",
  "name": "项目名称",
  "description": "项目说明，可为null"
}
```

请求还必须包含：

```text
HttpOnly Cookie: ts_session
Origin: http://127.0.0.1:3000 或 http://localhost:3000
X-Project-Request: 1
Content-Type: application/json
```

成功：

- 首次创建：`201`；
- 同一个`creation_id`、同一创建人、同一内容的安全重试：`200`；
- 响应体沿用`ProjectRead`：`id/code/name/description/lock_version/created_at/updated_at`；
- `Location`指向新项目详情。

失败：

- `401`：未登录；
- `403`：创建主体未列入允许名单、用户未启用、Origin或防跨站标记不正确；
- `409`：同一`creation_id`提交了不同内容、项目已被归档或成员资格已失效；
- `415`：不是JSON；
- `422`：字段校验失败；
- `503/504`：数据库账号未配置、权限不安全、数据库不可用或超时。

接口失败不会回退到Mock项目，也不会在前端自动换一个新的creation_id。超时后保留原表单，点击“重试并进入”复用原UUID。

### 2.2 `GET /v1/projects`

原响应增加：

```json
"capabilities": {"can_create": true}
```

按钮只依据这个能力显示；后端POST仍然独立鉴权。

## 4. 公司数据库操作总原则

下面的命令由用户在自己的机器执行。助手不连接公司服务器、不输入密码、不执行GRANT。必须按顺序执行，任何`STOP`或失败都停止并回传输出。

| 环境 | 用途 |
|---|---|
| Windows PowerShell | 校验、上传、建立SSH隧道、启动后端/前端 |
| Ubuntu SSH窗口 | 解包、只读检查、备份前检查、数据库授权 |
| 后端PowerShell窗口 | 读取两个数据库密码并启动FastAPI |
| 前端PowerShell窗口 | 启动Next.js |

## 8. Ubuntu：授权前备份

本次是新增数据库账号权限变化，必须使用授权前新备份。继续执行冻结R2包的只备份步骤；不要执行migrate/seed/bootstrap：


## 9. Ubuntu：在同一事务中授权新角色

只有第8节返回新的`BACKUP_RECEIPT`后执行。把下面的`BACKUP_RECEIPT`替换为第8节实际输出路径：

```bash
set -euo pipefail
cd "$HOME/ts-project-create-20260922-r1"
BACKUP_RECEIPT='/home/t7920/ts-db-backups/这里替换为第8节实际的.backup.json'

python3 project_create_step.py provision \
  --r2-dir "$HOME/ts-db-m0-20260921-r2" \
  --database ee_platform --port 5432 \
  --system-id 7686454253092706426 \
  --backup-receipt "$BACKUP_RECEIPT" \
  --confirm-create-role ee_project_api_create
printf 'PROVISION FINISHED. Password is not set. Send output; stop before password setting.\n'
```

这一步：

- 若账号不存在则创建`ee_project_api_create`；
- 若账号已存在但属性、成员关系或旧权限不符合预期，则停止，不自动修复；
- 给8张表SELECT、5张表INSERT；
- 不给UPDATE、DELETE、DDL或高权限；
- 与只读账号校验在同一事务中完成；
- 不写入任何业务项目，不改变测试项目。

## 10. Ubuntu：单独设置新账号密码

只有第9节成功后执行。密码不回传给助手、不写进命令历史；在Ubuntu交互式`psql`中输入：

```bash
sudo -u postgres /usr/lib/postgresql/18/bin/psql -X -w -h /var/run/postgresql -p 5432 -U postgres -d ee_platform
```

进入`psql`后：

```sql
\password ee_project_api_create
\q
```

`\password`会交互式读取两次密码。不要在SQL文件、PowerShell、`.env.example`或聊天中写明密码。

## 12. Windows：启动带双数据库账号的后端

先在一个新的**Windows PowerShell**窗口，建立已有SSH隧道；如果已有同一条隧道，不要重复建立：

```powershell

```

再在另一个**Windows PowerShell**窗口执行。此命令只在当前窗口生效：

```powershell
$ErrorActionPreference = 'Stop'
$ReaderSecure = Read-Host 'ee_project_api_ro数据库密码（不回显）' -AsSecureString
$ReaderCredential = [System.Management.Automation.PSCredential]::new('ee_project_api_ro', $ReaderSecure)
$ReaderPassword = [Uri]::EscapeDataString($ReaderCredential.GetNetworkCredential().Password)

$WriterSecure = Read-Host 'ee_project_api_create数据库密码（不回显）' -AsSecureString
$WriterCredential = [System.Management.Automation.PSCredential]::new('ee_project_api_create', $WriterSecure)
$WriterPassword = [Uri]::EscapeDataString($WriterCredential.GetNetworkCredential().Password)

$env:PROJECTS_DATABASE_URL = "postgresql://ee_project_api_ro:$ReaderPassword@127.0.0.1:15432/ee_platform?sslmode=require"
$env:PROJECTS_WRITE_DATABASE_URL = "postgresql://ee_project_api_create:$WriterPassword@127.0.0.1:15432/ee_platform?sslmode=require"
$env:PROJECTS_CREATE_SUBJECTS = 'engineer01'
$env:PROJECTS_WRITE_ORIGINS = 'http://127.0.0.1:3000,http://localhost:3000'

$ReaderPassword = $null; $WriterPassword = $null
$ReaderCredential = $null; $WriterCredential = $null
$ReaderSecure = $null; $WriterSecure = $null
Set-Location -LiteralPath 'E:\Git projects\TS-backend'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

不要使用`postgres`或`ee_m0_owner`作为应用连接账号。后端会同时使用读连接读取工作空间，使用独立创建连接执行5表事务。

## 14. 失败处理

- 第6节目标目录已存在：停止，不删目录、不覆盖。
- 第8节有其他客户端连接：停止，先正常关闭已知客户端。
- 第9节`Unexpected creator privilege`：停止，不自动REVOKE；回传完整输出。
- 第9节成功但第10节密码失败：不重复授权；只重新设置密码。
- POST返回504：保留表单点击“重试并进入”，不要刷新或再次点“新增项目”。
- POST返回503且提示创建账号未配置：检查后端PowerShell是否同时设置了两个DSN和`PROJECTS_CREATE_SUBJECTS`。
- 项目已创建但工作空间读取失败：不要再次创建；点击“重新加载工作空间”，检查读账号和SSH隧道。
- 不要运行任何`migrate`、`seed`、`bootstrap`、`DROP`、`TRUNCATE`或重建命令。
